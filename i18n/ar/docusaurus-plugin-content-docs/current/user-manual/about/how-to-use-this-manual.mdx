## النمط الذي تتبعه كل صفحة إجراء

الصفحات التي تصف شيئاً *تفعله* مكتوبة على الشكل نفسه، حتى إذا قرأت واحدة أمكنك تصفّح البقية. ولا تحتاج كل صفحة إلى كل العناوين، لكن الترتيب لا يتغير.

| العنوان | ما يخبرك به |
| --- | --- |
| **الدور** | من يقوم بهذا عادةً |
| **انتقل إلى** | مسار القائمة بالضبط |
| **الغرض** | لماذا توجد هذه الخطوة أصلاً |
| **قبل أن تبدأ** | ما ينبغي أن يكون قائماً |
| **ما تراه** | الشاشة، حقلاً بحقل حيث يهم ذلك |
| **ما يجب فعله** | الضغطة، في تعليمة واحدة |
| **ما تفعله SCOP** | ما يجري خلف الزر |
| **النتيجة المتوقعة** | كيف ينبغي أن تبدو الشاشة بعدها |
| **التحقق** | أين تذهب لتثبت أنه نجح |
| **قواعد العمل** | أي القواعد قد ترفض هذا الإجراء |
| **إذا لم ينجح** | العَرَض وما تتحقق منه، في جدول |
| **إجراءات ذات صلة** | الصفحات المجاورة |
| **التالي** | الخطوة التي تليها |

وينبغي أن تكون الإجابة عن سؤالين متاحةً دائماً من صفحة الإجراء: **ماذا أضغط الآن**، و**كيف أعرف أنه نجح**. فإن تركتك صفحة يوماً غير واثق من أحدهما، فذلك خلل في الدليل — نرجو الإبلاغ عنه.

## الاصطلاحات

### مسارات القوائم

تُكتب مسارات القوائم بأسهم وتبدأ دائماً من قائمة التطبيق:

```text
SCOP → Operations → Demands
```

والأسماء هي **أسماء واجهة Odoo الإنجليزية** كما هي دون تغيير، بما في ذلك في النسخة العربية. وهذا مقصود: فالواجهة بالإنجليزية، ومسارٌ يمكنك البحث عنه على الشاشة أنفع من مسارٍ مترجَم لا تجده.

### مراجع السجلات

تظهر المعرِّفات التجارية تماماً كما تطبعها SCOP.

| البادئة | الكائن |
| --- | --- |
| `DMD-` | طلب (Demand) |
| `SHP-` | شحنة (Shipment) |
| `PLN-` | خطة يومية (Daily Plan) |
| `TRP-` | رحلة (Trip) |

### الحالات

تُكتب أسماء الحالات **بخط عريض** وباسم SCOP نفسه لا بصياغة مقارِبة — مثل **Eligible for Planning**، لا *«جاهز للتخطيط»*. وحيث تناقش الصفحة القيمة التقنية المخزَّنة تُكتب `بنمط الكود`، مثل `eligible`.

### الأزرار والحقول

تُكتب أسماء الأزرار والحقول **بخط عريض** كما تظهر تماماً: **Mark Eligible**، و**Stage Everything**، و**Override Readiness**.

خلفية تشرح *لماذا* يتصرف النظام على هذا النحو. يمكن تخطّيها في القراءة الأولى، وتنفع حين يفاجئك شيء.

:::

:::note[ملاحظة]

تفصيل يسهل إغفاله ويهمّ أحياناً.

:::

:::warning[تحذير]

شيء سيكلّفك وقتاً أو يعطي نتيجة خاطئة إن أخطأت فيه. اقرأ هذه.

:::

:::danger[رفض]

ستوقفك هنا قاعدة عمل. وتذكر الصفحة اسم القاعدة وكيفية استيفائها.

:::

## الروابط المتقاطعة، ولماذا لا تُكرَّر الشروح

بعض الأفكار في SCOP تُصادَف في خمسة مواضع مختلفة — الملكية، وحالات الجاهزية الخمس، وفصل الاعتماد عن الإنشاء. وكل واحدة منها مشروحة **مرة واحدة** وبالكامل في صفحة واحدة، وكل صفحة أخرى تحيل إليها.

وهذا يبقي الشروح متسقة، ويعني أن تغيير قاعدة يتطلب تحديث صفحة واحدة بالضبط. والصفحات التي تملك كل فكرة هي:

| الفكرة | مشروحة بالكامل في |
| --- | --- |
| Odoo يملك المعاملة، و SCOP تملك العملية | [SCOP و Odoo](./scop-and-odoo.mdx) |
| الكميات الفعلية تأتي من تحويل Odoo | [التحقق من التسليم في Odoo](../execution/odoo-delivery-validation.mdx) |
| ما هو الطلب (Demand) | [إدارة الطلب](../demand/demand-management.mdx) |
| الملكية و `BR-INV-002` | [ملكية المخزون](../ownership/inventory-ownership.mdx) |
| الطلب الواحد ≠ شحنة واحدة | [التكوين والتجميع](../shipments/formation-and-consolidation.mdx) |
| حالات الجاهزية الخمس | [جاهزية المستودع](../readiness/warehouse-readiness.mdx) |
| فصل المهام و `BR-PLN-001` | [حوكمة الخطة](../planning/plan-governance.mdx) |
| ما يمكن للسائق الوصول إليه | [نموذج أمان السائق](../execution/driver-security-model.mdx) |
| OTIF | [OTIF](../reporting/otif.mdx) |
| قواعد العمل والبوابات وصلاحية الاعتماد | [نموذج الحوكمة](../concepts/the-governance-model.mdx) |

فإن وجدت الشرح نفسه مكتوباً مرتين، فأحدهما قديم. ثِق بالصفحة المرجعية.

## لقطات الشاشة

كل لقطة شاشة في هذا الدليل مأخوذة من تطبيق الإصدار الأول. والشاشات تتغير؛ فإن اختلفت لقطة عمّا تراه، **فالتطبيق هو الصحيح والدليل هو الخطأ** — نرجو الإبلاغ عن ذلك.

وتُلتقط شاشات السائق بعرض الهاتف، لأن هذه هي طريقة استخدامها.
