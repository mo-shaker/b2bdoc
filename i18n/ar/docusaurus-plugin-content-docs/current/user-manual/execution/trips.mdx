**الدور**
المخطِّط يملك النموذج الكامل. **والسائق لا يراه أبداً** — بل يستخدم [My Work](./driver-delivery.mdx).

**انتقل إلى**
`SCOP → Operations → Trips`

## ما هي الرحلة

**مركبة** واحدة و**سائق** واحد ينفّذان سلسلة **محطات** في يوم واحد.

وتُنشئ الرحلةَ دورةُ تخطيط ضمن خطة يومية. ولا تُنشئ واحدة يدوياً في التشغيل الطبيعي.

## العروض

| العرض | استخدمه لـ |
| --- | --- |
| **القائمة** | رحلات اليوم بحالتها ومركبتها وسائقها وعدد محطاتها |
| **التقويم** | رؤية اليوم موزَّعاً على الوقت |
| **المحاور** | [المخطَّط مقابل الفعلي للرحلة](../reporting/trip-planned-vs-actual.mdx) |

:::note[Trips مخفية عن قائمة السائق]

يقدّم `Operations → Trips` نموذج المُوزِّع الكامل. ويصل السائق إلى رحلاته عبر `My Work → My Trips` الذي يقدّم نموذجاً مبسَّطاً مصمَّماً للهاتف.

وإخفاء القائمة تسهيل. أما الأمان فقاعدة السجلات تحته — [نموذج أمان السائق](./driver-security-model.mdx).

:::

### الترويسة

| الحقل | المعنى |
| --- | --- |
| **Reference** | `TRP-2026-000006` |
| **Vehicle** | أي مركبة |
| **Driver** | أي سائق. **والفراغ يعني ألّا أحد يرى هذه الرحلة** |
| **Route** | مسار رئيسي، إن انطبق |
| **Planned Start / End** | النافذة المقصودة |
| **Actual Start / End** | ما حدث |
| **Stop Count / Stops Completed** | التقدّم |
| **Capacity Feasible** | هل تتّسع الحمولة عند **كل** نقطة |
| **First Breach Sequence** | أين لا تتّسع، إن لم تتّسع |
| **Peak Weight % / Peak Volume %** | أقصى امتلاء تبلغه المركبة |
| **Outcome** | يُضبط عند إغلاق الرحلة |

:::warning[الرحلة بلا سائق لا تظهر في My Trips لأحد]

وأشيع سبب أن المخطِّط تنقصه **Employees → Officer** في Odoo، فلا يُكمل حقل **Driver** تحميل خياراته.

→ [مرجع الصلاحيات](../roles/permissions-reference.mdx)

:::

### التبويبات

| التبويب | يحتوي |
| --- | --- |
| **Stops** | التسلسل، بالوصول والخدمة والمغادرة مخطَّطةً وفعليةً |
| **Loads** | ما هو على المركبة فعلياً |
| **Capacity** | الحمولة عند كل نقطة من التسلسل |
| **Planned vs Actual** | المدة والمسافة والتكلفة، مخطَّطة مقابل فعلية |
| **Resources Held** | إسنادات المركبة والسائق وحالتها |
| **Loading** | مهام التحميل لهذه الرحلة |

## السعة — تُفحص عند كل نقطة

هذا هو الجزء الذي يفاجئ الناس.

:::info[الرحلة التي تتّسع عند المغادرة قد تظل مستحيلة]

الرحلة المختلطة بين استلام وتسليم **تغيّر حمولتها بعد كل محطة**. فالمركبة التي تغادر المستودع ضمن حدّها قد تتجاوزه في منتصف المسار بعد استلام.

فتتحقق SCOP من الحمولة عند **كل نقطة من تسلسل المحطات**، لا عند المغادرة وحدها.

:::

يعرض تبويب **Capacity** صفاً لكل نقطة:

| العمود | المعنى |
| --- | --- |
| **Sequence** | أين على المسار |
| **Stop** | أي محطة |
| **Used / Remaining Weight** و**Weight %** | صورة الوزن عند تلك النقطة |
| **Used / Remaining Volume** و**Volume %** | صورة الحجم |
| **Feasible** | هل تستطيع المركبة حملها هنا |
| **Limiting Dimension** | أكثر بُعد مقيس امتلاءً عند هذه النقطة |
| **Breached Dimensions** | ما تجاوز المركبة، إن تجاوز |

و**Compute Capacity** في الترويسة يعيد حسابه. و**First Breach Sequence** يخبرك أين تنظر أولاً.

:::danger[Capacity Feasible = false لا تعني دائماً «غير مجدية»]

الحقل يكون false **متى لم يُجسَّد منحنى سعة**، ويشمل ذلك رحلة لم تُحسب سعتها قط.

ميّز بينهما بقراءة الصف بجانبه:

| Capacity Feasible | First Breach Sequence | الذروة % | المعنى |
| --- | --- | --- | --- |
| false | رقم محطة حقيقي | غير صفري | **غير مجدية فعلاً.** أصلِح الحمولة |
| false | `0` | `0` | **لم تُحسب.** اضغط **Compute Capacity** |
| true | — | غير صفري | مجدية |

**مُتحقَّق منه على `b2b`:** أظهرت `TRP-2026-000006` **Capacity Feasible = false** بتسلسل تجاوز صفري وذروات صفرية، بينما قُيِّم `BR-RTE-001` عند `trip_approve` و`trip_release` و**نجح**، مسجّلاً *"Feasible at every point of the sequence."* فالقاعدة كانت محقّة؛ والحقل ببساطة لم يجد منحنى يقرؤه.

:::

:::warning[Compute Capacity يحتاج صلاحيات مسؤول النظام]

يظهر الزر لكل من يستطيع فتح رحلة، لكنه يُنشئ لقطات سعة، و**مجموعة مسؤول SCOP وحدها يجوز لها إنشاؤها**. ومدير العمليات الذي يضغطه يحصل على:

```text
You are not allowed to create 'SCOP Trip Capacity Snapshot'
(scop.trip.capacity.snapshot) records.
This operation is allowed for the following groups:
  - SCOP/Administrator
```

مُسجَّل كعيب — راجع [نطاق الإصدار الأول](../about/release-1-scope.mdx).

:::

ويستطيع مسؤول النظام قراءة البيانات نفسها عبر كل الرحلات في `SCOP → Technical → Capacity Snapshots`، والمجموع في [استغلال المركبات](../reporting/vehicle-utilization.mdx).

## تقديرات التكلفة

يحسب **Estimate Cost** تكلفة مخطَّطة من معدلات تكلفة المركبة، ويسجّل **إصدار معدل التكلفة** المستخدَم.

| الحقل | المعنى |
| --- | --- |
| **Planned Cost Estimate** | قبل الرحلة |
| **Execution Cost Estimate** | بناءً على ما حدث فعلاً |
| **Cost Estimate Variance** | الفرق |
| **Cost Rate Version** | أي معدلات طُبِّقت |

:::warning[معدلات التكلفة تقديرات تشغيلية لا أرقام محاسبية]

هي موجودة لتُقارَن خطتان. ولا شيء يطابقها بدفتر الأستاذ، ولا يجوز اقتباسها كتكلفة مبيعات أبداً.

→ [نطاق الإصدار الأول](../about/release-1-scope.mdx)

:::

## الموارد المحجوزة

`SCOP → Operations → Resource Assignments`، أو تبويب **Resources Held** في الرحلة.

<Screenshot
  src="user-manual/10-resource-assignments.png"
  alt="قائمة إسنادات الموارد في SCOP تعرض المركبات والسائقين المحجوزين للرحلات بحالة إسنادهم."
  caption="الإسنادات المُلتزَم بها وحدها متعارضة فيما بينها."
/>

إسناد المورد هو حجز مركبة أو سائق لرحلة. وله ثلاث حالات ذات معنى:

| الحالة | المعنى |
| --- | --- |
| **Candidate** | قيد النظر. وقد تحجز خطتان متنافستان المركبة نفسها كمرشَّحة |
| **Reserved** | أُطلقت الخطة. والمورد محجوز |
| **Committed** | أُطلقت الرحلة. وهذا التزام تشغيلي |

:::info[الالتزامات التشغيلية وحدها متعارضة فيما بينها]

قد تنظر خطتان في المركبة نفسها في الوقت نفسه — وهذا هو *معنى* التخطيط. لكن لا يمكن أن تلتزما بها معاً.

:::

وتُنشأ الإسنادات عند **إطلاق** الرحلة لا عند صياغتها. فالرحلة غير المُطلَقة لا تحجز شيئاً، وصفوف المرشَّحين الذين لن يخرجوا ستجعل عرض التعارضات غير مقروء.

:::warning[الرحلة بلا نافذة مخطَّطة لا تستطيع حجز مواردها]

وإطلاق رحلة بلا بداية ونهاية مخطَّطتين مرفوض.

:::

**مُتحقَّق منه على `b2b`:** أطلقت خطةٌ رحلةً فأصبح إسناد مركبتها **committed** فوراً، وأُنشئت مهمتا تحميل — واحدة لكل شحنة.

### الحجز المزدوج

إسنادان مُلتزَم بهما على المركبة نفسها في النافذة نفسها تعارض. اقرأ القائمة مجمَّعة حسب المركبة لاكتشافه.

## قاعدتا عمل الرحلة

### BR-RTE-001 — يجب أن يكون التسلسل ممكناً عند كل نقطة

| | |
| --- | --- |
| **الشدّة** | **حاجبة** |
| **تُطلَق عند** | `trip_approve`، `trip_release`، `load_confirm` |
| **إن تعذّر تقييمها** | **حجب** |

يجب أن تتّسع الحمولة في المركبة عند كل نقطة من التسلسل. وإن لم تتّسع، تعذّر اعتماد الرحلة أو إطلاقها — وتعذّر كذلك إطلاق الخطة التي تحملها، تحت `BR-PLN-002`.

| العلاج | كيف |
| --- | --- |
| قلّل الحمولة | انزع شحنة من الرحلة |
| غيّر المركبة | استخدم واحدة بسعة أكبر |
| أعِد ترتيب المحطات | سلّم قبل أن تستلم |

### BR-RTE-002 — ينبغي ألّا يكون استغلال المركبة مهدِراً

| | |
| --- | --- |
| **الشدّة** | **تحذير** |
| **تُطلَق عند** | `trip_approve`، `trip_release` |
| **إن تعذّر تقييمها** | تسجيل والمضي |

**يحذّر ولا يحجب.** فالمركبة نصف الفارغة صحيحة أحياناً — فالتزامات العملاء تعلو على الاستغلال في ملف الأهداف.

**والعتبة 50% ذروة استغلال.** والرسالة كما ظهرت على `b2b`:

```text
Peak utilisation is only 0.0%, below the 50% the plan aims for.
```

**وأُطلقت الخطة طبيعياً مع بقاء هذا التحذير قائماً.** والتحذيرات المستمرة عبر رحلات كثيرة تستحق القراءة كإشارة حجم أسطول لا كخطأ.

→ [استغلال المركبات](../reporting/vehicle-utilization.mdx)

## الأزرار

| الزر | متاح حين | الدور |
| --- | --- | --- |
| **Recommend** | Draft | المخطِّط |
| **Submit** | Recommended أو Modified | المخطِّط |
| **Modify** | Under Review | المخطِّط |
| **Approve** | Under Review أو Modified | مدير العمليات |
| **Release** | Approved | مدير العمليات |
| **Estimate Cost** | ليست Completed ولا Cancelled | المخطِّط |
| **Compute Capacity** | دائماً | **مسؤول النظام** — راجع التحذير أعلاه |
| **Start Loading** | Released | المستودع |
| **Loading Done** | Loading | المستودع |
| **Depart** | Ready to Depart | **السائق** أو المُوزِّع |
| **Complete** | In Progress أو Exception | المخطِّط |
| **Raise Exception** | Loading أو Ready to Depart أو In Progress | المخطِّط |
| **Resume** | Exception | المخطِّط |
| **Cancel** | Draft أو Recommended أو Approved أو Released أو Exception | المخطِّط |

الانتقالات كاملةً: [دورة حياة الرحلة](./trip-lifecycle.mdx).

## من يجوز له إطلاق المغادرة

مساران، وكلاهما مشروع:

| من | كيف |
| --- | --- |
| **السائق المُسنَد** | حق خاص بالنموذج: مغادرة رحلتك من صلاحية السائق |
| **مخطِّط / مُوزِّع** | عبر صلاحية اعتماد `depart` المُهيّأة |

ولا أحد غيرهما. فمستخدم المستودع الذي يملك صلاحية كتابة على الرحلات **ليس** مخوَّلاً بذلك بالتالي — فإمكانية الوصول ليست تخويلاً.

**مُتحقَّق منه على `b2b`:** غادر السائق رحلته بنفسه بنجاح.

## التحقق

| تحقّق | أين |
| --- | --- |
| أن للرحلة مركبة وسائقاً | ترويسة الرحلة |
| أنها ممكنة السعة | **Capacity Feasible** في الترويسة |
| أين تتجاوز، إن تجاوزت | **First Breach Sequence** ثم تبويب **Capacity** |
| أن مواردها محجوزة | تبويب **Resources Held** |
| وجود مهام التحميل | تبويب **Loading** |
| أن السائق يراها | اطلب منه فتح `My Work → My Trips` |

## إذا لم ينجح

| العَرَض | السبب |
| --- | --- |
| **Capacity Feasible** false | `BR-RTE-001` — اقرأ **First Breach Sequence**؛ والصفر يعني «لم تُحسب» |
| **Release** يُرفض | الرحلة غير ممكنة، أو لست مدير عمليات |
| الخطة لا تُطلَق بسبب هذه الرحلة | `BR-PLN-002` — أصلِح الرحلة أو انزعها |
| السائق لا يرى الرحلة | لا سائق مُسنَد، أو الرحلة غير مُطلَقة |
| **Depart** غير معروض | الرحلة ليست **Ready to Depart** — مهمة تحميل ما زالت مفتوحة |
| الموارد غير محجوزة | الرحلة بلا نافذة مخطَّطة |
| **Compute Capacity** يرفع خطأ وصول | إنشاء لقطات السعة لمسؤول النظام وحده |
| مركبة على رحلتين | افحص حالات الإسناد — **committed** وحدها متعارضة |
