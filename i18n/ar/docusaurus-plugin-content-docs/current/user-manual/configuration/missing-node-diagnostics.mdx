**الأدوار**
مسؤول النظام يقرأ الأحداث. وأي أحد يستطيع الإبلاغ عن العَرَض.

**انتقل إلى**
`SCOP → Technical → Domain Events`

## العَرَض

أمر تسليم موجود في Odoo، وداخل نطاق التجربة، وأُنشئ بعد الإطلاق — **ولا يوجد له طلب**.

## السبب

أحد طرفَي التحويل أو كلاهما لا يُحَل إلى **أي عقدة تخطيط**.

| الطرف | يُحَل من |
| --- | --- |
| **المنشأ** | موقع المخزون المصدر، والشريك |
| **الوجهة** | موقع المخزون الوجهة، والشريك |

فإن أخفق أيٌّ منهما، لم تُنشئ SCOP طلباً.

:::info[هذا مقصود لا خلل]

الطلب الذي لا تستطيع SCOP رسم مساره ولا قياسه أسوأ من لا طلب: إذ سيبقى في السجل إلى الأبد، ويجرّ تغطية الخطة إلى أسفل، ولن يكون قابلاً للتخطيط أبداً.

لكنه **ليس صامتاً**. فكل تخطٍّ يُسجَّل.

:::

## إيجاد التحويلات المتخطّاة

`SCOP → Technical → Domain Events` ← رشِّح **Event Name** = `DemandGenerationSkipped`

| الحقل على الحدث | يخبرك بـ |
| --- | --- |
| **Subject** | أي تحويل تُخطّي |
| **Event Name** | `DemandGenerationSkipped` |
| **Error Message** | النتيجة كاملةً، في جملة |
| **Payload** | موقع المخزون غير المربوط، والشريك، و**أي طرف** أخفق |
| **State** | Processed — فالتخطّي نفسه سُجِّل بنجاح |

أُعيد إنتاجه على `b2b` بالتسليم إلى فرع بلا عقدة:

```text
No SCOP planning node resolves the destination location 'Partners/Customers'
for SCOP Manual Demo Customer, SCOP Manual Branch C, so no demand was created
for QSD/OUT/00012. Map the location to a SCOP location, then re-save the transfer.
```

وإلى جانبها الحمولة:

```json
{ "reason": "no_scop_planning_node",
  "missing_endpoint": "destination",
  "stock_location": "Partners/Customers",
  "partner": "SCOP Manual Demo Customer, SCOP Manual Branch C",
  "picking": "QSD/OUT/00012" }
```

و`missing_endpoint` هو الحقل الذي يُقرأ أولاً: فهو يقول هل أخفق **المنشأ** أم **الوجهة**، حتى لا تفحص الطرف الخطأ.

## إصلاحه

| # | الخطوة | أين |
| --- | --- | --- |
| 1 | اقرأ حمولة الحدث — أي موقع، وأي طرف | `Technical → Domain Events` |
| 2 | أنشئ عقدة التخطيط لذلك الموقع أو صحّحها | `Master Data → Locations` |
| 3 | اربطها بـ**الشريك** أو **المستودع** أو **موقع المخزون** المسمّى في الحمولة | نموذج العقدة |
| 4 | أكمِل الإحداثيات والمنطقة الزمنية ونافذة فتح واحدة على الأقل | نموذج العقدة |
| 5 | **أعِد حفظ التحويل** في Odoo | Odoo |
| 6 | أكّد ظهور الطلب | `Operations → Demands` |

:::info[لماذا تنجح إعادة الحفظ]

علامة التخطّي تُحفَظ **منفصلةً** عن علامة النجاح، عن قصد.

فلو سُجِّل التخطّي على أنه *«عولج»*، لما فعل ربط العقدة لاحقاً وإعادة حفظ التحويل شيئاً — إذ ستظن SCOP أن العمل أُنجز بالفعل.

وإبقاؤهما منفصلتين هو ما يجعل المشكلة قابلةً للاستدراك.

:::

وإعادة الحفظ تكفي. فلا تحتاج إلى إلغاء التحويل وإعادة إنشائه.

## إصلاحه نهائياً

تحويلٌ واحد متخطًّى ثغرةُ بيانات. وعشرون ثغرةُ إعدادات.

| النمط | السبب الجذري | العلاج |
| --- | --- | --- |
| كل تسليم إلى عميل واحد | فرع ذلك العميل بلا عقدة | أنشئها |
| كل تسليم من مستودع واحد | عقدة المستودع مفقودة أو غير مربوطة | أنشئها أو اربطها |
| كل تسليم إلى منطقة كاملة | لم يُنشئ أحد عقداً لتلك الفروع | استخدم `Master Data → Import Locations` |
| متفرّق، عملاء شتّى | تُنشأ العقد بردّ الفعل كلما ظهر عميل | اجعل إنشاء العقدة جزءاً من تسجيل العميل |

:::warning[إنشاء العقدة ليس تلقائياً]

إنشاء عميل في Odoo **لا** يُنشئ عقدة تخطيط. فإن ظهر عملاء جدد بانتظام، وجب أن يُنشئ أحدهم عقدتهم، وإلا لم يُنتج أول تسليم لهم شيئاً في صمت.

اجعلها جزءاً من مسار تسجيل العملاء.

:::

## تمييزه عن الأسباب الأخرى

ليس كل طلب مفقود عقدةً مفقودة. اعمل من أعلى إلى أسفل بهذا الترتيب:

| # | افحص | أين | العَرَض |
| --- | --- | --- | --- |
| 1 | هل القائمة مُرشَّحة؟ | شريط بحث قائمة الطلبات | الطلب موجود |
| 2 | هل نوع العملية في النطاق؟ | `Technical → Pilot Scope` | **لا حدث إطلاقاً** |
| 3 | هل طُبِّقت التجربة؟ | الشاشة نفسها | **لا حدث إطلاقاً** |
| 4 | هل أُنشئ التحويل قبل الإطلاق؟ | التحويل | **لا حدث إطلاقاً** |
| 5 | هل كانت عقدة مفقودة؟ | `Technical → Domain Events` | **حدث `DemandGenerationSkipped`** |
| 6 | هل أخفق التوليد؟ | `Reporting → Failed Projections` | **حدث فاشل برسالة خطأ** |

:::note[الإشارة الفارقة هي وجود حدث من عدمه]

**لا حدث إطلاقاً** يعني أن SCOP لم تنظر في التحويل أصلاً — فقد كان خارج النطاق، أو قبل الإطلاق.

**وحدث تخطٍّ** يعني أنها نظرت فيه وامتنعت عمداً.

**وحدث فاشل** يعني أنها حاولت وساء شيء.

:::

## الإسقاطات الفاشلة

`SCOP → Reporting → Failed Projections` *(مسؤول النظام)*

توليد الطلبات **غير حاجب بالتصميم**. فإن أخفق، تراجَع من تلقاء نفسه وظل التحويل يُحفَظ — إذ يجب ألّا يعجز مشغّل مستودع عن تسجيل حركة بسبب مشكلة في إسقاط تخطيطي.

وثمن ذلك أن الإخفاقات هادئة لحظة وقوعها.

| الحقل | الاستخدام |
| --- | --- |
| **Error Class** | أي نوع من الإخفاق |
| **Error Message** | التفصيل |
| **Attempts** | كم مرة حُوول |
| **First Failure At** و**Last Attempt At** | النافذة |

عالِج السبب، ثم أعِد حفظ التحويل.

وخلال التجربة، تستحق هذه الشاشة نظرةً يومية.

## التحقق

| تحقّق | أين | توقّع |
| --- | --- | --- |
| أن العقدة صارت موجودةً ومربوطة | `Master Data → Locations` | مكتملة |
| أن إعادة الحفظ أنتجت طلباً | `Operations → Demands` | الطلب |
| أن حدث `DemandGenerated` كُتب | `Technical → Domain Events` | حدث واحد |
| ألّا تخطٍّ جديداً | الشاشة نفسها، مُرشَّحة | لا شيء بعد الإصلاح |
| ألّا تبقى التغطية مبخوسة | `Reporting → Orphan Moves` | فارغ |
