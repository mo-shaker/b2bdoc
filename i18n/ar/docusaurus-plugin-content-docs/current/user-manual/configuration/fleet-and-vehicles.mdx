**الأدوار**
المخطِّط يصون الإتاحة. ومسؤول النظام يصون ما عداها.

**انتقل إلى**
Odoo **Fleet → Vehicles**، ثم حقول SCOP؛ إضافةً إلى
`SCOP → Master Data → Vehicle Availability`

:::note[هذا ليس دليلاً عاماً لوحدة Fleet في Odoo]

فلا يُغطَّى إلا ما تضيفه SCOP وتستخدمه. أما التسجيل والصيانة والعقود وقراءات العداد فموضوع وحدة Fleet نفسها.

:::

## الحقل الواحد الذي يوقف التخطيط

:::danger[المركبة بلا ملف سعة لا يمكن استخدامها]

يُرشِّح مزوّد التخطيط على المركبات التي تعلن **ملف سعة**. والمركبة بلا ملف غير مرئية للتخطيط.

فإن عاد **كل** طلب في التشغيلة بـ*No feasible vehicle*، فالسبب المعتاد ليس نقص أسطول. بل أن لا مركبة مختارة تحمل ملف سعة.

:::

## خصائص SCOP على المركبة

| الحقل | المعنى |
| --- | --- |
| **Capacity Profile** | الأبعاد التي تُقاس بها هذه المركبة، وحدودها |
| **Compartments** | أقسام تُحمَّل منفصلةً، لكلٍّ ملفه |
| **Restrictions** | أين ومتى لا يجوز أن تذهب |
| **Availability** | متى يمكن استخدامها |
| **Home Location** | عقدة التخطيط التي تبدأ منها وتنتهي إليها |
| **Average Speed (km/h)** | تُستخدَم لتقدير السفر |
| **Handling Capabilities** | ماذا تستطيع أن تحمل — رافعة خلفية، تبريد |
| **Cost per km** و**Cost per hour** و**Fixed cost per trip** | تقديرات تكلفة التخطيط |
| **Cost Rate Version** | أي نسخة من المعدلات تنطبق |
| **Planning Ready** | هل تملك المركبة ما يحتاجه التخطيط |

و**Planning Ready** أسرع فحص مفرد. فإن كان خطأً، لم يستخدم التخطيط المركبة.

## ملفات السعة

`SCOP → Master Data → Capacity Profiles`

ملف السعة يسمّي **الأبعاد** التي تُقاس بها المركبة والحدّ في كلٍّ منها.

| البعد المعتاد | الوحدة |
| --- | --- |
| الوزن | كجم |
| الحجم | م³ |

وتُتحقَّق السعة عند **كل نقطة في تسلسل المحطات** لا عند المغادرة فقط — لأن الرحلة المختلطة بين استلام وتسليم تُغيّر الحمولة بعد كل محطة.

→ [الرحلات](../execution/trips.mdx)

## المقصورات

المركبة ذات الأقسام المُحمَّلة منفصلةً — مقصورة مبرَّدة وأخرى عادية مثلاً — تعلن كلاً منها مقصورةً بملف سعتها وقدرات مناولتها.

| الحقل | المعنى |
| --- | --- |
| **Name** | المقصورة |
| **Sequence** | ترتيب التحميل |
| **Capacity Profile** | حدودها هي |
| **Handling Capabilities** | ماذا تستطيع أن تحمل |

## القيود

أين ومتى لا يجوز للمركبة أن تذهب.

| نوع القيد | مثال |
| --- | --- |
| **Zone** | غير مسموح بها في وسط المدينة |
| **Time of day** | لا تسليمات ليلية |
| **Legal** | قيد تنظيمي |
| **Load type** | لا تستطيع حمل صنف من البضائع |

ولكلٍّ **Valid From** و**Valid To**، فالقيد المؤقت ينقضي من تلقاء نفسه.

والطلب الذي لا تستطيع مركبةٌ غير مقيَّدة خدمته يعود غير مخطَّط بسبب *Route restriction*.

## إتاحة المركبة

`SCOP → Master Data → Vehicle Availability` *(المخطِّط)*

| الحقل | المعنى |
| --- | --- |
| **Vehicle** | أي مركبة |
| **From** / **To** | الفترة |
| **Availability Type** | Available · Maintenance · Blocked |
| **Reason** | لماذا |

ولا يستخدم التخطيط إلا المركبات **Available** للنافذة التي يخطّطها.

:::note[سجّل الصيانة قبل التخطيط لا بعده]

المركبة المحجوزة للورشة الثلاثاء القادم يجب أن تُسجَّل غير متاحة **قبل** توليد خطة الثلاثاء. فلا سبيل للتخطيط إلى معرفة ذلك غير هذا.

:::

## معدلات التكلفة

| الحقل | يُستخدَم لـ |
| --- | --- |
| **Cost per km** | تكلفة على أساس المسافة |
| **Cost per hour** | تكلفة على أساس الزمن |
| **Fixed cost per trip** | رسمٌ لكل رحلة |
| **Cost Rate Version** | يُسجَّل على الرحلة، فيبقى التقدير الماضي قابلاً للتفسير |

:::warning[معدلات التكلفة تقديرات تشغيلية لا أرقام محاسبية]

وُجدت ليُقارَن بها خطتان. ولا شيء يوفّقها مع دفتر الأستاذ، ويجب ألّا تُذكَر أبداً بوصفها تكلفة مبيعات.

→ [نطاق الإصدار الأول](../about/release-1-scope.mdx)

:::

وزر **Estimate Cost** على الرحلة يحسب تكلفةً مخطَّطة منها ويسجّل أي نسخة استُخدمت.

## تخصيصات الموارد — كيف تُحجَز مركبة

<Screenshot
  src="user-manual/10-resource-assignments.png"
  alt="قائمة تخصيصات الموارد في SCOP تعرض المركبات والسائقين المحجوزين للرحلات بحالة تخصيصهم."
  caption="التخصيصات المُلزِمة وحدها متنافية."
/>

`SCOP → Operations → Resource Assignments` *(المخطِّط)*

التخصيص يحجز مركبةً أو سائقاً لرحلة، على مدى نافذة.

| الحالة | المعنى |
| --- | --- |
| **Candidate** | قيد النظر |
| **Reserved** | أُطلقت الخطة. والمورد محجوز |
| **Committed** | أُطلقت الرحلة. التزامٌ تشغيلي |
| **Closed** | انتهت الرحلة |
| **Cancelled** | أُلغيت الرحلة |

:::info[خطتان قد تنظران في المركبة نفسها. وواحدة فقط تلتزم بها]

التمييز بين مرشَّح ومحجوز ومُلزَم هو ما يتيح لخطط متنافسة أن تنظر في المركبة نفسها — وهو *جوهر* التخطيط — مع إبقاء الالتزامات التشغيلية متنافية.

:::

وتُنشأ التخصيصات حين **تُطلَق** الرحلة لا حين تُسوَّد. فالرحلة غير المُطلَقة لا تحجز شيئاً، وأسطرُ مرشَّحين لن يطيروا أبداً كانت ستجعل شاشة التعارضات غير قابلة للقراءة.

:::warning[الرحلة بلا نافذة مخطَّطة لا تستطيع حجز مواردها]

فإطلاق رحلة كهذه يُرفض. اضبط البدء والانتهاء المخطَّطين أولاً.

:::

### الحجز المزدوج

تخصيصان مُلزِمان على المركبة نفسها في النافذة نفسها تعارض. اقرأ القائمة مُجمَّعةً بالمركبة لرصده.

## المناولة والتوافق

| الفهرس | الغرض |
| --- | --- |
| **Handling Profiles** | كيف يجب أن يُناوَل الصنف — مبرَّد، قابل للكسر |
| **Compatibility Groups** | ما لا يجوز أن يسافر معاً |

و**Handling Capabilities** للمركبة يجب أن تغطي ما تحتاجه الشحنة، وإلا عاد الطلب غير مخطَّط.

→ [الفهارس](./catalogues.mdx)

## تهيئة مركبة لـ SCOP — قائمة التحقق

| # | اضبط | وإلا |
| --- | --- | --- |
| 1 | **Capacity Profile** | لا يستطيع التخطيط استخدامها إطلاقاً |
| 2 | **Home Location** | المسارات بلا نقطة بدء |
| 3 | **Average Speed** | تقديرات السفر خاطئة |
| 4 | **Handling Capabilities** | لن تُعرَض عليها أعمال تستطيعها |
| 5 | **معدلات التكلفة** | تقديرات التكلفة فارغة |
| 6 | **الإتاحة** | ستُخطَّط وهي في الورشة |
| 7 | **القيود**، حيث تنطبق | سترسَل حيث لا يجوز أن تذهب |

ثم أكّد أن **Planning Ready** صحيح.

## التحقق

| تحقّق | أين | توقّع |
| --- | --- | --- |
| أن المركبة جاهزة للتخطيط | حقول SCOP على المركبة | **Planning Ready** صحيح |
| أنها تظهر في المعالج | `Planning → Generate a Plan` | في **Available Vehicles** |
| أن سعتها محترَمة | تبويب **Capacity** في الرحلة | ممكنة عند كل نقطة |
| أنها محجوزة لرحلتها | `Operations → Resource Assignments` | **Committed** |
| أن الاستغلال معقول | [استغلال المركبات](../reporting/vehicle-utilization.mdx) | ذروة معقولة |

## إذا لم ينجح

| العَرَض | السبب |
| --- | --- |
| `Access Error` على `Vehicle` عند التخطيط | المخطِّط ينقصه **Fleet → Administrator** في Odoo |
| المركبة لا تُعرَض | لا ملف سعة، أو ليست متاحةً لتلك النافذة |
| كل طلب يعود *No feasible vehicle* | لا مركبة مختارة تحمل ملف سعة |
| الطلبات تعود *Route restriction* | قيدٌ يستبعد كل المرشحات |
| الرحلة غير ممكنة سعوياً | `BR-RTE-001` — اقرأ **First Breach Sequence** |
| تنبيه استغلال على كل رحلة | `BR-RTE-002` — إشارة حجم أسطول لا خطأ |
| مركبة واحدة على رحلتين في آن | افحص حالات التخصيص — **المُلزِم** وحده متنافٍ |
| تقديرات التكلفة فارغة | لا معدلات تكلفة على المركبة |
