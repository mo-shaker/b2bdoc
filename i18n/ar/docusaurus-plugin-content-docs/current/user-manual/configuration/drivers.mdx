**الأدوار**
مسؤول النظام يهيّئ. والمخطِّط يصون الإتاحة ويخصّص.

**انتقل إلى**
Odoo **Employees**، إضافةً إلى `SCOP → Master Data → Driver Qualifications` و
`→ Driver Availability`

## السجلات الثلاثة وراء سائق واحد

السائق ثلاثة أشياء مترابطة، ولا بد من وجودها جميعاً.

```text
Odoo User          ← كيف يسجّل الدخول
    ↕ مربوط
Odoo Employee      ← سجل السائق، بعلامة "Is Driver"
    ↕ مخصَّص
SCOP Trip          ← العمل
```

| السجل | الغرض | إن غاب |
| --- | --- | --- |
| **User** بدور **Driver** في SCOP | تسجيل الدخول ورؤية **My Work** | لا يستطيع الدخول، أو لا يرى قائمة SCOP |
| **Employee** بعلامة سائق، **مربوط بذلك المستخدم** | إمكان تخصيصه لرحلة | لا يمكن تخصيص الرحلة، وتبقى **My Trips** فارغة |
| **تخصيص الرحلة** | العمل نفسه | لا شيء ليُفعل |

:::danger[ربط الموظف بالمستخدم هو ما يفوت الناس]

قواعدُ السجلات التي تمنح السائق رحلاته تطابق على **حساب المستخدم المربوط بالموظف**، لا على سجل الموظف وحده.

فالموظف الموسوم سائقاً وغير المربوط بحساب مستخدم يمكن أن تُخصَّص له رحلة **لن يراها أحد أبداً**.

:::

## خصائص SCOP على الموظف

| الحقل | المعنى |
| --- | --- |
| **Is Driver** | يجعل الموظف قابلاً للتخصيص للرحلات |
| **Qualifications** | الرخص والشهادات التي يحملها |
| **Availability** | المناوبات والغيابات والحجوب |
| **Max Daily Driving (min)** | الحدّ النظامي أو حدّ السياسة. والافتراضي 480 دقيقة |
| **Home Location** | عقدة التخطيط التي يبدأ منها وينتهي إليها |
| **Has Valid Qualifications** | محسوب — هل انتهت صلاحية شيء |

## أنواع المؤهلات

`SCOP → Master Data → Qualification Types`

أنواع المؤهلات التي يمكن أن يحملها سائق.

| الحقل | المعنى |
| --- | --- |
| **Name** | ما هو |
| **Code** | مرجع قصير |
| **Requires Expiry** | هل يجب على الحامل تسجيل تاريخ انتهاء |
| **Description** | التفصيل |

## مؤهلات السائقين

`SCOP → Master Data → Driver Qualifications`

من يحمل ماذا.

| الحقل | المعنى |
| --- | --- |
| **Employee** | السائق |
| **Qualification Type** | ما يحمله |
| **Reference** | رقم الرخصة أو الشهادة |
| **Issued Date** | متى |
| **Expiry Date** | متى تنقضي |
| **Valid** | محسوب — هل هي سارية الآن |

:::warning[المؤهل المنتهي ليس تنبيهاً بل قيداً]

يستخدم التخطيط المؤهلات حين يشترطها العمل. والسائق الذي انقضت رخصته يُنتج *No qualified driver* على الطلبات التي تحتاجها — لا إشعاراً.

راقب **Has Valid Qualifications** على الموظف، وراجِع تواريخ الانتهاء قبل أن تصير مهمة.

:::

## إتاحة السائق

`SCOP → Master Data → Driver Availability` *(المخطِّط)*

| الحقل | المعنى |
| --- | --- |
| **Employee** | السائق |
| **From** / **To** | الفترة |
| **Availability Type** | Shift · Absence · Blocked |
| **Max Driving Minutes** | حدٌّ لهذه الفترة تحديداً |
| **Reason** | لماذا |

| النوع | المعنى |
| --- | --- |
| **Shift** | هو يعمل |
| **Absence** | إجازة، مرض |
| **Blocked** | غير متاح لسبب آخر |

ويستخدم التخطيط السائقين الذين على **مناوبة** للنافذة المخطَّطة.

:::note[سجّل الغياب قبل التخطيط لا بعده]

السائق المُجاز الثلاثاء القادم يجب أن يُسجَّل غائباً **قبل** توليد خطة الثلاثاء. فلا سبيل للتخطيط إلى معرفة ذلك، والخطة المبنية حول سائق غائب لا بد أن تُعاد.

:::

## تخصيص سائق لرحلة

حقل **Driver** على الرحلة.

:::warning[حقل Driver يحتاج Odoo Employees → Officer]

فبدونها لا ينتهي الحقل من تحميل خياراته أبداً، فلا يمكن اختيار سائق — والرحلة بلا سائق لا تظهر في **My Trips** لأحد.

وهذه ثاني أشيع مشكلة صلاحيات في نشرٍ جديد، بعد Fleet.

→ [مرجع الصلاحيات](../roles/permissions-reference.mdx)

:::

## ماذا يحدث حين تكون الرحلة بلا سائق

| العاقبة | التفصيل |
| --- | --- |
| الرحلة **غير مرئية** في **My Trips** | لا أحد يملكها |
| **Depart** لا يستطيع سائق ضغطه | فلا سائق مخصَّص |
| ويستطيع المُرسِل **مع ذلك** تسييرها | عبر صلاحية اعتماد `depart` |
| وتظل الرحلة تُحمَّل ويمكن أن تكتمل | لكن لا أحد يسجّل الوصول ولا إثبات التسليم |

:::danger[الرحلة بلا سائق ليست خطأً تمنعك SCOP من ارتكابه]

لا شيء يرفض إطلاق رحلة بلا سائق. والعَرَض يظهر لاحقاً، حين يبلّغ سائق أن **My Trips** فارغة.

افحص عمود **Driver** في قائمة الرحلات قبل إطلاق خطة.

:::

## تهيئة سائق جديد — قائمة التحقق

| # | الخطوة | أين |
| --- | --- | --- |
| 1 | أنشئ مستخدم Odoo | إعدادات Odoo |
| 2 | امنحه دور **Driver** في SCOP — **ولا شيء غيره** | فئة SCOP لدى المستخدم |
| 3 | أنشئ سجل الموظف أو جِده | Odoo Employees |
| 4 | ضع علامة **Is Driver** | الموظف |
| 5 | **اربط الموظف بحساب المستخدم** | الموظف |
| 6 | سجّل المؤهلات | `Master Data → Driver Qualifications` |
| 7 | سجّل المناوبات | `Master Data → Driver Availability` |
| 8 | اضبط الموقع الأصلي وحدّ القيادة اليومي | الموظف |
| 9 | سجّل الدخول باسمه وأكّد ظهور **My Work** | — |

:::danger[لا تُضِف SCOP User إلى سائق أبداً]

`SCOP User` يمنح قراءةً عبر العملية كلها — كل طلب، وكل شحنة، وكل خطة.

وتظل قواعد السجلات تضيّق رحلاته، لكن كل ما عداها ينفتح.

→ [نموذج أمن السائق](../execution/driver-security-model.mdx)

:::

## التحقق

| تحقّق | أين | توقّع |
| --- | --- | --- |
| أن الموظف موسوم سائقاً | Odoo Employees | **Is Driver** صحيح |
| أنه مربوط بمستخدم | الموظف | حساب مستخدم |
| أن المستخدم يحمل دور Driver وحده | فئة SCOP لديه | Driver فقط |
| أن المؤهلات سارية | **Has Valid Qualifications** | صحيح |
| أنه متاح | `Master Data → Driver Availability` | مناوبة تغطي اليوم |
| أنه قابل للتخصيص | حقل **Driver** في الرحلة | يظهر |
| أنه يرى رحلته | سجّل الدخول باسمه | تظهر في **My Trips** |

## إذا لم ينجح

| العَرَض | السبب | العلاج |
| --- | --- | --- |
| حقل **Driver** لا يُحمَّل أبداً | المخطِّط ينقصه **Employees → Officer** في Odoo | امنحها |
| السائق ليس في القائمة | ليس موسوماً **Is Driver**، أو غير متاح ذلك اليوم | صحّح الموظف أو الإتاحة |
| **My Trips** فارغة | لا رحلة مخصَّصة، ولا مُطلَقة، أو **الموظف غير مربوط بالمستخدم** | افحص الثلاثة |
| الطلبات تعود *No qualified driver* | لا أحد متاح يحمل المؤهل | سجّله، أو خصّص من يحمله |
| مؤهل لا يُحتسَب | انتهت صلاحيته | جدّده وحدّث تاريخ الانتهاء |
| السائق يرى عمل غيره | يحمل `SCOP User` كذلك | أزِله |
