## الغرض

القائمة التشغيلية في `Planning → Unplanned Demand` تقول لك **ما تصلحه اليوم**. وهذا التقرير يقول لك **ما الذي يظل يحدث**.

البيانات نفسها، والسؤال مختلف.

## الجمهور

المخطِّط/المُرسِل والإدارة.

## انتقل إلى

`SCOP → Reporting → Unplanned Demand`

## المُرشِّحات

يفتح مُجمَّعاً بـ**السبب**. رشِّح بمدى التواريخ لمقارنة الفترات.

## الأبعاد

<Screenshot
  src="user-manual/61-report-unplanned-demand.png"

| البعد | الاستخدام |
| --- | --- |
| **Reason** | بُعد الصفوف الافتراضي. أي قيد يكلّف أكثر |
| **Plan Date** | بُعد الأعمدة الافتراضي. كيف يتغيّر عبر الزمن |
| **Customer** | أي العملاء يُخدَمون دون الكفاية |
| **Next Action** | ماذا اقترح المزوّد |
| **Plan** | أي تشغيلة |

## المقاييس

عدد الطلبات غير المخطَّطة. ولا مقياس آخر — فالقيمة في التجميع.

## كيف تقرؤه

<Screenshot
  src="quick-start/41-report-unplanned-demand.png"
  alt="تقرير الطلبات غير المخطَّطة في SCOP مُجمَّعاً بالسبب."
  caption="السبب على الصفوف وتاريخ الخطة على الأعمدة. وسببٌ واحد مهيمن هو الإشارة المطلوبة."
/>

| ما تراه | ما يعنيه | ماذا تفعل |
| --- | --- | --- |
| سبب واحد يهيمن كل يوم | قيدٌ ممنهج | أصلِح القيد لا الطلبات |
| سبب يظهر ثم يتوقف | شيءٌ أُصلِح | أكّد أنه يبقى مُصلَحاً |
| موزَّع بالتساوي على الأسباب | احتكاك تشغيلي عادي | اعمل على القائمة اليومية |
| قفزة في تاريخ واحد | شيءٌ تغيّر ذلك اليوم | افحص ماذا — عقدة، أو مركبة، أو تغيير نطاق |
| عميل واحد متركّز | عقدته أو تعهداته مضبوطة خطأً | افحص العقدة |

## مثال

أسبوعٌ مُجمَّع بالسبب وتاريخ الخطة:

```text
Reason                    Mon  Tue  Wed  Thu  Fri
Warehouse not ready         4    3    5    4    6
No feasible vehicle         0    0    0    0    0
Missing required data      11    0    0    0    0
Lower priority              1    2    1    2    1
```

ثلاث قراءات:

| السطر | القراءة |
| --- | --- |
| **Missing required data**، الاثنين فقط | عقدةٌ كانت ناقصةً وأُصلِحت. مُعالَج |
| **Warehouse not ready**، كل يوم، ومتصاعد | تراكم تجهيز مستمر. وهذا ما يُصعَّد |
| **Lower priority** | النظام يتخذ خيارات حقيقية بسعة محدودة. صحّي |

## أخطاء التفسير الشائعة

| الخطأ | لماذا هو خطأ |
| --- | --- |
| عدّ المجموع هو العنوان | **التوزيع** هو النتيجة لا المجموع |
| عدّ *Lower priority* إخفاقاً | يعني أن للنظام خياراً حقيقياً واتخذه صحيحاً |
| قراءته بلا [تغطية الخطة](./plan-coverage.mdx) | عشرون غير مخطَّط من خمسة وعشرين يختلف كثيراً عن عشرين من مئتين |
| افتراض أن الانخفاض تحسّن | قد يعني كذلك أن طلباً أقل صار مؤهَّلاً |
| تجاهل الأسطر الناتجة عن إلغاء التخطيط | الطلب المرفوع عن خطة يكتب سطراً هنا كذلك |

:::note[أمران يكتبان سطراً هنا]

تشغيلةٌ **عجزت عن وضع** طلب، وطلبٌ **رُفِع عن** خطة أو أُلغيت خطته.

وكلاهما مشروع. فإن بدا عدد يومٍ مرتفعاً وقد أُلغيت فيه خطة، فهذا هو السبب.

:::

:::warning[انخفاض العدد ليس خبراً ساراً تلقائياً]

فإن صار طلبٌ أقل مؤهَّلاً — لأن الملكية غير محلولة، أو الجاهزية ضعيفة — عُرِض أقل على التشغيلة، وعاد أقل غير مخطَّط.

اقرأه دائماً مقابل عدّ **Offered** في تغطية الخطة.

:::
