## مسؤوليتك

أنت تقرأ العملية. **ولا تغيّر شيئاً.**

فالإدارة دور موجّه للقراءة: يضيف لوحة المعلومات وجاهزية التجربة إلى ما يراه مستخدم SCOP أصلاً، ولا يمنح أي صلاحية تشغيلية.

## قوائمك

| القائمة | السؤال الذي تجيب عنه |
| --- | --- |
| `SCOP → Dashboard` | ماذا يجري اليوم؟ |
| `Reporting → Plan Coverage` | هل خطّطنا كل ما كان قابلاً للتخطيط؟ |
| `Reporting → OTIF` | هل سلّمنا في الوقت وبالكامل؟ |
| `Reporting → Vehicle Utilization` | هل تُستخدم المركبات كما ينبغي؟ |
| `Reporting → Trip Planned vs Actual` | كم الخطة قريبة من الواقع؟ |
| `Reporting → Exception Ageing` | أي مشكلات تجاوزت موعدها؟ |
| `Reporting → Decision Quality` | كم مرة تُتجاوز التوصية؟ |
| `Reporting → Unplanned Demand` | ما الذي نعجز عنه باستمرار؟ |
| `Master Data → Onboarding → 3 · Pilot Readiness` | هل التجربة جاهزة للانطلاق؟ |

## الأسئلة الخمسة الأسبوعية

| السؤال | التقرير | كيف تبدو الإجابة السيئة |
| --- | --- | --- |
| هل نخطّط كل ما نستطيع؟ | [تغطية الخطة](../reporting/plan-coverage.mdx) | تغطية أقل بكثير من 100% بلا تفسير |
| ما الذي يوقفنا؟ | [الطلب غير المخطَّط](../reporting/unplanned-demand-report.mdx) | سبب واحد يهيمن كل يوم |
| هل نفي بوعودنا؟ | [OTIF](../reporting/otif.mdx) | انخفاض «في الوقت» مع ثبات «بالكامل» — مشكلة جدولة لا مخزون |
| هل المركبات مناسبة للعمل؟ | [استغلال المركبات](../reporting/vehicle-utilization.mdx) | ذروة استغلال منخفضة باستمرار |
| هل نثق بالتوصية؟ | [جودة القرار](../reporting/decision-quality.mdx) | معدل تعديل مرتفع مع تكرار سبب التجاوز نفسه |

## قراءة OTIF بصدق

:::warning[ليس كل تسليم قابلاً للقياس]

تحسب OTIF التسليمات التي تحمل **التزاماً** فقط. والتسليم بلا وعد لا يُحسب متأخراً — بل لا يُحسب أصلاً.

فجمّع دائماً حسب **Has Commitment** قبل استخلاص نتيجة، وإلا كنت تتوسّط مقاماً يتغيّر شكله.

:::

الشرح الكامل: [OTIF](../reporting/otif.mdx).

## ما لا يجوز لك

| غير مسموح | من يقوم به |
| --- | --- |
| اعتماد خطة أو إطلاقها | مدير العمليات |
| تغيير أي سجل تشغيلي | المخطِّط والمستودع |
| تغيير الإعدادات | مسؤول النظام |

وإن احتجت كذلك إلى التصريح بالخطط، فأنت بحاجة إلى دور **مدير العمليات** إضافةً — وسيظل `BR-PLN-001` يرفض خطة أنشأتها بنفسك.

## جاهزية التجربة

يُجري `Master Data → Onboarding → 3 · Pilot Readiness` فحصاً ويبلّغ بما إذا كانت متطلبات الانطلاق مستوفاة — النطاق مُطبَّق، والعقد مربوطة، والملكية مُرحَّلة.

استخدمه قبل قرار الانطلاق، لا كشاشة يومية. راجع [التهيئة والترحيل](../configuration/onboarding-and-migration.mdx).
