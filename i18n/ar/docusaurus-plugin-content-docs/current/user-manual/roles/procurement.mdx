## مسؤوليتك

أنت تملك **ما وعد به المورّد**، وتراقب الحركات الواردة التي ينتجها ذلك الوعد.

والمشتريات دور خفيف في الإصدار الأول. فمعظم عملك يبقى في Odoo Purchase؛ و SCOP تضيف سجل الالتزام ووضوح الوارد.

## قوائمك

| القائمة | لماذا تستخدمها |
| --- | --- |
| `Master Data → Supplier Commitments` | ما وعد به المورّد، ومتى |
| `Operations → Demands` | الطلبات الواردة المُولَّدة من الإيصالات |
| `Reporting → Operation Timeline` | إعادة بناء عملية وارد واحدة |

وكل ما يستطيع مستخدم SCOP قراءته تستطيع قراءته.

## التزامات المورّدين

يسجّل التزام المورّد ما تعهّد المورّد بتسليمه، ومتى.

| الحقل | المعنى |
| --- | --- |
| **Partner** | المورّد |
| **Product** و**Unit** | ماذا وعد وبأي وحدة |
| **Qty Committed** | كم |
| **Expected Date** | متى |
| **Location** | أين ينبغي أن يصل |
| **Source Document** | أمر الشراء خلفه |
| **Status** | Open · Received · Cancelled |

وهو النظير المورِّدي لـ[التزام الخدمة](../configuration/service-commitments.mdx)، الذي يسجّل ما وعدنا *نحن* به عميلاً.

## الطلب الوارد

حين يُنشئ Odoo **إيصالاً** نوع عمليته داخل نطاق التجربة، تولّد SCOP طلباً بـ:

| الحقل | القيمة |
| --- | --- |
| **Demand Type** | **Inbound** |
| **Origin Type** | **Procurement Requirement** إن كان خلفه أمر شراء، وإلا **Supplier Collection** |

ثم يتبع الطلب دورة الحياة نفسها كأي طلب آخر — راجع [دورة حياة الطلب](../demand/demand-lifecycle.mdx).

## ما ليس في الإصدار الأول

:::note[نطاق المشتريات ضيّق عمداً]

| غير متاح | ملاحظة |
| --- | --- |
| شروط الأمانة على أمر الشراء | ملكية الأمانة تأتي من **شريك مُعلَّم** لا من شروط الأمر — راجع [ملكية المخزون](../ownership/inventory-ownership.mdx) |
| تقارير أداء المورّدين | لا يوجد نظير لـ OTIF للمورّدين في الإصدار الأول |
| تنبيهات آلية للمورّدين | لا توجد |

:::

## ما لا يجوز لك

| غير مسموح | من يقوم به |
| --- | --- |
| التحقق من الطلبات أو تخطيطها | المخطِّط |
| اعتماد الخطط | مدير العمليات |
| تعليم شريك كمالك أمانة | مسؤول النظام، عبر Onboarding |
