## مسؤوليتك

أنت تملك **الوعد** والمتطلب الذي خلفه. ومعظم عملك يجري في Odoo على أمر البيع. أما SCOP فهي حيث تتحقق ممّا آل إليه.

## ما تفعله فعلياً

| المهمة | أين |
| --- | --- |
| تأكيد أمر العميل | **Odoo** — المبيعات |
| ضبط تاريخ التسليم الموعود به | **Odoo** — على الأمر |
| التأكد من أن SCOP التقطت الأمر | `SCOP → Operations → Demands` |
| الإجابة عن *«أين تسليمي؟»* | الطلب، ورحلته |
| التأكد من الوفاء بالوعد | `SCOP → Reporting → OTIF` |

:::info[أنت لا تُنشئ الطلبات]

يُنشأ الطلب **تلقائياً** حين يُنشئ Odoo أمر تسليم داخل النطاق. فلا توجد خطوة «طلب جديد»، ولا ينبغي أن تبحث عنها.

راجع [كيف تُنشأ الطلبات](../demand/how-demands-are-created.mdx).

:::

## قوائمك

| القائمة | لماذا تستخدمها |
| --- | --- |
| `Operations → Demands` | التأكد من التقاط المتطلب، ومتابعته |
| `Operations → Shipments` | كيف سيتحرك المتطلب |
| `Operations → Trips` | متى سيخرج |
| `Master Data → Service Commitments` | قراءة ما وُعِد به |
| `Reporting → OTIF` | هل وُفِّي بالوعد |
| `Reporting → Operation Timeline` | إعادة بناء تسليم واحد من أوله لآخره |

## التزام الخدمة

**تاريخ التسليم على أمر البيع** يصبح سجل SCOP لما وُعِد به. ويُلتقط **مرة واحدة**، عند توليد الطلب.

| إذا | فإن |
| --- | --- |
| الأمر يحمل تاريخ تسليم | يصبح **التزام تاريخ**، وتقيس OTIF مقابله |
| الأمر بلا تاريخ تسليم | تُستخدم ساعات عمل الوجهة كـ**التزام نافذة** |
| لا هذا ولا ذاك | **لا التزام**، ولا يُحسب التسليم متأخراً أبداً |

وتغيير تاريخ الأمر **بعد** وجود الطلب لا يعيد كتابة الالتزام المُلتقَط. فإن نقل عميل تاريخاً، أخبِر المخطِّط — راجع [التزامات الخدمة](../configuration/service-commitments.mdx).

## الإجابة عن «أين تسليمي؟»

1. افتح `SCOP → Operations → Demands`.
2. ابحث عن **رقم أمر المصدر**، مثل `S09520`.
3. اقرأ **حالة** الطلب.

| الحالة | قل للعميل |
| --- | --- |
| **Draft** و**Submitted** | استُلم، ولم يُراجَع بعد |
| **Validated** | روجِع، بانتظار المستودع |
| **Eligible for Planning** | جاهز للجدولة |
| **Planned** | مُجدوَل، والخطة لم تُعتمد بعد |
| **Released** | مُجدوَل ومُصرَّح به، وسيخرج |
| **In Execution** | على المركبة الآن |
| **Completed** | سُلِّم بالكامل |
| **Partially Completed** | سُلِّم جزء، والباقي على طلب مؤجَّل |
| **Failed** | لم يُسلَّم — راجع السبب على المحطة |
| **Rejected** و**Cancelled** | لن يُسلَّم كما طُلب |

ولمعرفة المركبة والتوقيت، افتح تبويب **Shipments** في الطلب وتابع الشحنة إلى رحلتها.

## ما لا يجوز لك

| غير مسموح | من يقوم به |
| --- | --- |
| التحقق من طلب أو تأهيله | المخطِّط |
| تغيير الكميات | Odoo، على التحويل — المستودع |
| بناء خطة أو اعتمادها | المخطِّط ثم مدير العمليات |
| تغيير التزام مُلتقَط | لا أحد. يُلتقط مرة واحدة بالتصميم |

## إذا كان هناك خلل

| العَرَض | تحقّق من |
| --- | --- |
| لا طلب لأمر مؤكَّد | قد يكون نوع العملية خارج نطاق التجربة، أو الوجهة بلا عقدة تخطيط — راجع [لا طلب أُنشئ](../troubleshooting/demand-problems.mdx) |
| الطلب يُظهر وجهة خاطئة | عنوان التسليم يُحَل إلى عقدة تخطيط أخرى — أخبِر مسؤول النظام |
| تسليم غائب عن OTIF | قد لا يحمل التزاماً — راجع [OTIF](../reporting/otif.mdx) |
| الطلب عالق في **Submitted** | الملكية غالباً غير محلولة — أخبِر المخطِّط. راجع [ملكية المخزون](../ownership/inventory-ownership.mdx) |
