**الدور**
المخطِّط / المُوزِّع

**انتقل إلى**
`SCOP → Planning → Generate a Plan`

## الغرض

شاشة واحدة تسأل: أي يوم تخطّط، وبماذا تخطّط، ومن ينبغي أن يفكّر. وكل ما عدا ذلك يتبع الأجوبة.

## قبل أن تبدأ

| تحقّق | أين |
| --- | --- |
| الطلبات في **Eligible for Planning** | `Operations → Demands` مجمَّعة حسب الحالة |
| شحناتها **قابلة للتخطيط** | `Operations → Warehouse Readiness` |
| للمركبات **ملف سعة** | حقول SCOP على المركبة |
| تحمل **Fleet → Administrator** في Odoo | وإلا `Access Error` على `Vehicle` |
| تحمل **Employees → Officer** في Odoo | وإلا تعذّر إسناد سائق |

| الحقل | المعنى | الافتراضي |
| --- | --- | --- |
| **Plan Date** | اليوم المُخطَّط له. **إلزامي** | اليوم |
| **Objective Profile** | الأهداف المرتَّبة التي يُخطَّط تجاهها | SCOP Standard Objectives |
| **Planned By** | أي مزوّد قرار يُستخدم | المزوّد الافتراضي المُهيّأ |
| **Demands** | الطلبات المؤهلة المعروضة لهذا التاريخ | مملوءة مسبقاً |
| **Available Vehicles** | المركبات التي يجوز لهذه الدورة استخدامها | اخترها |
| **Assignments** | أزواج طلب-مركبة، للتخطيط **اليدوي** فقط | فارغة |
| **Timeout (seconds)** | كم تنتظر المزوّد | 60 |

### Plan Date

التاريخ المُخطَّط له، لا تاريخ تخطيطك. ويصبح جزءاً من معرِّف الخطة — فـ`PLN-2026-08-25-01` هي أول خطة بُنيت ليوم 25 أغسطس.

ولا تُعرض إلا الطلبات التي يطابق تاريخها المطلوب.

### Objective Profile

قائمة الأهداف المرتَّبة. اتركها على الملف القياسي ما لم يكن لديك سبب محدد.

→ [نظرة عامة على التخطيط](./planning-overview.mdx)

### Planned By

| الخيار | استخدمه حين |
| --- | --- |
| **Baseline** | تريد توصية لتراجعها |
| **Manual** | تريد التخطيط يدوياً مع التحقق والتقييم |

:::info[اليدوي ليس التفافاً]

يأخذ المزوّد اليدوي **الإسنادات** التي تُدخلها، ويتحقق منها بالقواعد نفسها، وينتج شكل الجواب نفسه. فتصبح خطتك قابلة للمقارنة بما كانت ستكون عليه التوصية.

:::

### Available Vehicles

المركبات التي يجوز لهذه الدورة النظر فيها. والمركبة غير المذكورة هنا لن تُستخدم.

:::warning[المركبة بلا ملف سعة لا يمكن استخدامها]

يصفّي المزوّد على المركبات التي تُعلن ملف سعة. فإن لم يكن لأيٍّ من المركبات التي اخترتها ملف سعة، عاد **كل** طلب غير مخطَّط بسبب *No feasible vehicle*.

→ [الأسطول والمركبات](../configuration/fleet-and-vehicles.mdx)

:::

### Timeout

كم تنتظر المزوّد قبل تسجيل إخفاق. وستون ثانية وافرة للمزوّد الأساسي الحتمي. لا تزدها إلا إذا كانت الدورات تنتهي مهلتها فعلاً.

## ما يجب فعله

اضبط التاريخ، وأكِّد الطلبات والمركبات، ثم اضغط **Generate**.

## ما تفعله SCOP

1. تبني **طلباً** — الطلبات والمركبات وسعاتها والنوافذ والمسافات والمعدلات، كلها محلولة إلى قيم.
2. تفتح **دورة تخطيط** وتسجّل الطلب.
3. تستدعي المزوّد المختار.
4. تسجّل **الجواب** والمدة التي استغرقها.
5. تُنشئ **خطة يومية** بحالة **Generated**، ورحلاتها بحالة **Recommended**.
6. تكتب صف **طلب غير مخطَّط** لكل طلب لم يتّسع، ولكلٍّ سبب.

:::info[الطلب حامل للقيم]

كل ما يحتاجه المزوّد محلول داخل الطلب قبل استدعائه — السعات والنوافذ والمسافات والمعدلات. وهذا ما يجعل الدورة **قابلة لإعادة التشغيل**: فإعادة تشغيلها لاحقاً تستخدم المدخلات التي كانت لديها فعلاً، لا البيانات الرئيسية اليوم.

→ [دورات التخطيط](./planning-runs.mdx)

:::

## النتيجة المتوقعة

| الكائن | الحالة |
| --- | --- |
| دورة التخطيط | **Recommended** |
| الخطة اليومية | **Generated** |
| الرحلات | **Recommended** |
| الطلبات التي وُضعت | **Planned** |
| الطلبات التي لم توضع | ما زالت **Eligible for Planning**، مع صف غير مخطَّط |

## التحقق

| تحقّق | أين |
| --- | --- |
| وجود الخطة | `Planning → Daily Plans` |
| أن الدورة سجّلت طلبها وجوابها | `Planning → Planning Runs` |
| أن الرحلات معقولة | تبويب **Trips** في الخطة |
| ما لم يتّسع، ولماذا | تبويب **Unplanned Demand** في الخطة |
| أن كل رحلة ممكنة السعة | تبويب **Capacity** في الرحلة |

## اقرأ الطلب غير المخطَّط قبل أي شيء آخر

<Screenshot
  src="quick-start/17-unplanned-demand.png"

الخطة ذات عدد الرحلات المرتفع وعدد غير المخطَّط المرتفع ليست خطة جيدة. اقرأ الأسباب قبل مراجعة الرحلات.

→ [الطلب غير المخطَّط](./unplanned-demand.mdx)

## قواعد العمل

التوليد نفسه لا يحمل بوابة. وتُطلَق القواعد لاحقاً، عند اعتماد الخطة ورحلاتها وإطلاقها:

| القاعدة | تُطلَق عند |
| --- | --- |
| `BR-RTE-001` جدوى السعة عند كل نقطة | `trip_approve`، `trip_release` |
| `BR-RTE-002` تحذير الاستغلال | `trip_approve`، `trip_release` |
| `BR-PLN-001` فصل المهام | `plan_approve`، `plan_release` |
| `BR-PLN-002` منع إطلاق رحلة محجوبة | `plan_release` |

## إذا لم ينجح

| العَرَض | السبب | العلاج |
| --- | --- | --- |
| `Access Error` على `Vehicle` | نقص **Fleet → Administrator** في Odoo | Fleet → *Officer* لا يكفي |
| لا طلبات معروضة | لا شيء **Eligible for Planning** لذلك التاريخ | [أهلية التخطيط](../demand/planning-eligibility.mdx) |
| كل شيء يعود *No feasible vehicle* | لا مركبة مختارة تُعلن ملف سعة | [الأسطول والمركبات](../configuration/fleet-and-vehicles.mdx) |
| طلب كبير يعود *Capacity shortage* | الحمولة تتجاوز المركبات المتاحة | قسّم الشحنة أو استخدم مركبة أكبر |
| كل شيء يعود *Warehouse not ready* | الشحنات غير قابلة للتخطيط | [جاهزية المستودع](../readiness/warehouse-readiness.mdx) |
| كل شيء يعود *Missing required data* | عقد تنقصها إحداثيات أو منطقة زمنية أو ساعات عمل | [عقد التخطيط](../configuration/planning-nodes.mdx) |
| طلب بملكية غير محلولة رُفض | صحيح. يُرفض قبل أي شيء آخر | [ملكية المخزون](../ownership/inventory-ownership.mdx) |
| الدورة **Failed** | المزوّد رفع خطأ أو انتهت مهلته | [دورات التخطيط](./planning-runs.mdx) |
| الخطة موجودة بلا رحلات | لم يمكن وضع شيء. اقرأ أسباب عدم التخطيط | [الطلب غير المخطَّط](./unplanned-demand.mdx) |
| المسارات بلا معنى | عقدة غير مُحدَّثة الإحداثيات، فمسافاتها مجهولة | [عقد التخطيط](../configuration/planning-nodes.mdx) |
