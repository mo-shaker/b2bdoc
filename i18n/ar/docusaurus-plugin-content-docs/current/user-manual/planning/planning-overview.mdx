## لماذا يوجد التخطيط

يحوّل التخطيط كومة متطلبات مستقلة إلى **يوم تشغيل واحد منسَّق**: أي مركبات تذهب إلى أين، وبأي ترتيب، وبأي حمولة، ومن يقودها.

وينتج **توصية**. يراجعها شخص، ويصرّح بها شخص آخر.

## السلسلة

```mermaid
flowchart LR
    ELIG["طلب مؤهَّل<br/>+ شحنة قابلة للتخطيط"]
    WIZ["Generate a Plan<br/>(المعالج)"]
    RUN["دورة التخطيط<br/>الطلب · الجواب · التوقيت"]
    PLAN["الخطة اليومية<br/>بحالة Generated"]
    TRIP["الرحلات<br/>بحالة Recommended"]
    UNP["الطلب غير المخطَّط<br/>مع السبب"]

    ELIG --> WIZ --> RUN
    RUN --> PLAN --> TRIP
    RUN --> UNP
```

## ما يحتاجه التخطيط قبل أن يعمل

| المتطلب | من أين يأتي | إن غاب |
| --- | --- | --- |
| طلبات في **Eligible for Planning** | [أهلية التخطيط](../demand/planning-eligibility.mdx) | لا شيء يُخطَّط |
| شحناتها **قابلة للتخطيط** | الجاهزية **Ready** أو **Conditionally Ready** | تُرفض بسبب *Warehouse not ready* |
| **الملكية محلولة** على كل سطر | [ملكية المخزون](../ownership/inventory-ownership.mdx) | تُرفض قبل النظر في أي شيء آخر |
| مركبات لها **ملف سعة** | [الأسطول والمركبات](../configuration/fleet-and-vehicles.mdx) | تُرفض بسبب *No feasible vehicle* |
| عقد بـ**إحداثيات ومنطقة زمنية وساعات عمل** | [عقد التخطيط](../configuration/planning-nodes.mdx) | تُرفض بسبب *Missing required data* |
| **Fleet → Administrator** و**Employees → Officer** لك في Odoo | [مرجع الصلاحيات](../roles/permissions-reference.mdx) | `Access Error`، أو تعذّر إسناد سائق |

## مزوّدا القرار

يقدّم الإصدار الأول اثنين، ويختار بينهما حقل **Planned By** في المعالج.

| المزوّد | ما يفعله |
| --- | --- |
| **Baseline** | ينتج **توصية حتمية** من الطلب المؤهَّل والمركبات المتاحة |
| **Manual** | يأخذ **إسناداتك أنت** ويتحقق منها ويقيّمها |

:::info[كلاهما يمر بالمنفذ نفسه]

التخطيط اليدوي ليس التفافاً. فهو يبني الطلب نفسه، ويستدعي الخدمة نفسها، وينتج شكل الجواب نفسه — وهذا تحديداً ما يتيح مقارنة خطة المشغّل بتوصية لاحقاً.

واختيار **manual** فعل متعمَّد مع سجل.

:::

## ما هو المزوّد الأساسي فعلاً

:::warning[ليس تحسين مسارات بالذكاء الاصطناعي]

يُجري المزوّد الأساسي **تسع خطوات حتمية دون أي بحث محلي** — لا 2-opt، ولا محاكاة تلدين، ولا أي خوارزمية استكشافية.

فبالطلب نفسه يعيد الجواب نفسه في كل مرة. وليس متوقَّعاً أن يكون *جيداً*. بل متوقَّع أن يكون **ثابتاً وقابلاً للتفسير**.

:::

وهذا هو المقصد. فبلا توصية لا يوجد ما يُقارَن به خطة المشغّل، ولن يكون لـ[جودة القرار](../reporting/decision-quality.mdx) أساس تقيس منه.

### الخطوات التسع

| # | الخطوة | ما تفعله |
| --- | --- | --- |
| 1 | **اختيار الطلب المؤهَّل** | يأخذ الطلبات ذات الملكية المحلولة والحمولة غير الصفرية |
| 2 | **ترتيب الأولوية والالتزام** | العاجل أولاً، ثم المرتفع فالعادي فالمنخفض؛ والتعادل يُفَض حتمياً |
| 3 | **تصفية المركبات الممكنة** | يُبقي المركبات التي تُعلن ملف سعة |
| 4 | **فحص الملكية** | يرفض كل ما ملكيته مجهولة |
| 5 | **فحص التوافق** | يرفض بضائع لا يجوز أن تسافر معاً |
| 6 | **فحص السعة** | يتحقق من الحمولة عند **كل نقطة** من التسلسل |
| 7 | **فحص النافذة** | يحترم الالتزامات وساعات العمل |
| 8 | **الإدراج** | يضع الطلب في مسار |
| 9 | **الجواب** | يُصدر الرحلات، ويصنّف كل رفض بسبب |

:::info[الملكية غير المحلولة تُرفض أولاً لا أخيراً]

إن بلغ طلب مجهول الملكية دورة تخطيط، فتخطيطه سيضع بضائع مجهولة الحق على مركبة. ويُرفض في الخطوة 1، بسبب يقول ذلك بالضبط — فيُصلح المشغّل الملكية بدل البحث عن شاحنة.

:::

### ما لا يفعله عمداً

| لا يفعل | لماذا |
| --- | --- |
| **اختيار المستودع** | كل محطة تستخدم مصدر الطلب ووجهته. ولا يُعدَّد مستودع بديل ولا يُقيَّم |
| **اختيار مصدر المخزون** | السبب نفسه |
| **البحث المحلي / تحسين المسار** | الحتمية هي الخاصية المهمة هنا |
| **التعلّم من الخطط السابقة** | لا يُدرَّب أي نموذج |

وإن لم يُعِد خطة ممكنة، خطّط المشغّل يدوياً. فالمزوّد إضافي ولا يستطيع تعطيل العمليات.

### أمر أخير يستحق المعرفة

حيث لا تحمل مصفوفة السفر مسافةً لزوج من العقد، يعاملها المزوّد على أنها **كبيرة جداً** لا صفراً. فالمسافة المجهولة يجب ألّا تجعل عقدتين تبدوان متجاورتين وتتصدّران كل مسار.

ولهذا تُنتج العقدة غير المُحدَّثة الإحداثيات تسلسلاتٍ غريبة بدل تسلسلات خاطئة تبدو معقولة — راجع [عقد التخطيط](../configuration/planning-nodes.mdx).

## ملف الأهداف

`SCOP → Governance → Objective Profiles`

لا يُحسِّن التخطيط رقماً واحداً. بل يعمل نزولاً في **قائمة مرتَّبة**، ولا يُقايَض هدف أدنى بهدف أعلى أبداً.

| الرتبة | الهدف | يعني |
| --- | --- | --- |
| 1 | السلامة والقانون والملكية والامتثال الإلزامي | لا تنقل أبداً بضائع لا نملك حقاً فيها |
| 2 | الجدوى | لا تخطّط أبداً ما لا يمكن تنفيذه فعلياً |
| 3 | التزامات العملاء الإلزامية | فِ بالوعود التي قطعناها |
| 4 | الأولوية وحماية الخدمة | العمل العاجل أولاً |
| 5 | تغطية الطلب | خطّط أكبر قدر ممكن |
| 6 | توفّر الموارد | استخدم مركبات وسائقين متاحين فعلاً |
| 7 | استغلال السعة | املأ المركبات |
| 8 | كفاءة المسافة والوقت والتكلفة | أبقِه قصيراً ورخيصاً |
| 9 | التفضيلات التشغيلية | كل ما عدا ذلك |

:::info[لهذا تخرج مركبة نصف فارغة]

الاستغلال في الرتبة 7. والتزامات العملاء في الرتبة 3.

فتترك SCOP مركبة نصف فارغة بدل خرق وعد، وهذا هو الترتيب يعمل بشكل صحيح — لا فشل تخطيط.

:::

والملف القياسي هو **SCOP Standard Objectives** (`SCOP-STD`)، وهو الافتراضي.

## تقديرات السفر والخدمة

| التقدير | يأتي من |
| --- | --- |
| مسافة السفر ومدته | **مصفوفة السفر** بين العقد |
| مدة الخدمة عند عقدة | نموذج خدمة العقدة نفسها، لعدد السطور الذي تحمله الزيارة |
| مدة التحميل | المدة المخطَّطة لمهمة التحميل |

:::warning[هذه تقديرات بيانات رئيسية لا تنبؤات]

لا يوجد نموذج تنبؤ في الإصدار الأول. فلا يُتوقَّع زمن سفر، ولا تُقاس مخاطر وصول، ولا توجد تغذية بيانات لحظية.

→ [نطاق الإصدار الأول](../about/release-1-scope.mdx)

:::

## تقديرات التكلفة

تحمل الرحلة **تقدير تكلفة مخطَّطاً** مستمَداً من معدلات تكلفة المركبة، مع تسجيل إصدار المعدل المستخدَم.

:::note[معدلات التكلفة تقديرات تشغيلية لا أرقام محاسبية]

هي موجودة لتُقارَن خطتان. ولا شيء يطابقها بدفتر الأستاذ، ولا يجوز اقتباسها كتكلفة مبيعات أبداً.

:::

## ما ينتجه التخطيط

| الكائن | الحالة | المعنى |
| --- | --- | --- |
| **دورة التخطيط** | Recommended | المحاولة، بطلبها وجوابها محفوظين |
| **الخطة اليومية** | Generated | اليوم المقترح |
| **الرحلات** | Recommended | واحدة لكل مركبة مستخدَمة |
| **المحطات** | Planned | واحدة لكل زيارة فعلية |
| **الطلب غير المخطَّط** | — | صف لكل طلب لم يتّسع، مع السبب |
