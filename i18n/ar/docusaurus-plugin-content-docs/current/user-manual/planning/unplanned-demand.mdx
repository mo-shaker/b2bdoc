**الدور**
المخطِّط يتصرف بناءً عليه. والإدارة تقرأ النمط.

**انتقل إلى**
`SCOP → Planning → Unplanned Demand`، أو تبويب **Unplanned Demand** في الخطة نفسها

## ما هو

كل طلب **تعذّر على دورة التخطيط وضعه**، مع السبب وإجراء تالٍ مقترح.

:::info[هذه أنفع شاشة في التخطيط]

الخطة تخبرك بما تفعله. وهذه تخبرك بما **لا** تفعله، ولماذا — وهذا هو الجزء الذي يكلّف مالاً وعملاء.

اقرأها قبل مراجعة الرحلات.

:::

| العمود | المعنى |
| --- | --- |
| **Plan** | الخطة التي جاء منها |
| **Plan Date** | اليوم الذي كان يُخطَّط له |
| **Demand** | الطلب الذي لم يتّسع |
| **Requesting Party** | من يتأثر |
| **Reason** | لماذا لم يتّسع |
| **Next Action** | ما يقترحه المزوّد |
| **Detail** | شرح المزوّد نفسه، بالكلمات |

وتُفتح القائمة **مجمَّعة حسب السبب**، لأن السبب هو المقصود.

ويوجد كذلك عرض محاور ورسم بياني — `SCOP → Reporting → Unplanned Demand` — لقراءة النمط عبر الزمن. راجع [تقرير الطلب غير المخطَّط](../reporting/unplanned-demand-report.mdx).

## الأسباب الاثنا عشر

كل واحد، وما يعنيه فعلاً، وما تفعله.

### No available inventory

| | |
| --- | --- |
| **يعني** | لا مخزون يُخصَّص لهذا الطلب |
| **تحقّق من** | تبويب **Allocations** في الطلب؛ وتوفّر تحويل Odoo |
| **العلاج** | جدّد المخزون، أو أعِد التخطيط لتاريخ يتوفر فيه |
| **صعّد إلى** | المشتريات، إن تكرر لمنتج واحد |

### Warehouse not ready

| | |
| --- | --- |
| **يعني** | جاهزية الشحنة ليست **Ready** ولا **Conditionally Ready** |
| **تحقّق من** | `Operations → Warehouse Readiness` — اقرأ **Evidence** |
| **العلاج** | يعتمد على الدليل. جهّز البضائع، أو احجز المخزون، أو حلّ الملكية |
| **صعّد إلى** | المستودع |

وهو أشيع سبب في التنصيب الجديد.

→ [جاهزية المستودع](../readiness/warehouse-readiness.mdx)

### No feasible vehicle

| | |
| --- | --- |
| **يعني** | **لا مركبة في الدورة تُعلن ملف سعة إطلاقاً** |
| **نص التفصيل** | *"No vehicle in this run declares a capacity profile."* |
| **تحقّق من** | المركبات التي اخترتها — هل **Planning Ready** صحيحة على كل واحدة؟ |
| **العلاج** | أسند ملف سعة لمركبة واحدة على الأقل في الدورة |
| **صعّد إلى** | من يملك بيانات الأسطول الرئيسية |

:::warning[هذا سبب إعدادات لا سبب حجم أسطول]

يصفّي المزوّد على المركبات التي تُعلن ملف سعة. فإن لم تفعل أيٌّ منها، تعذّر عليه النظر في أي مركبة، فعاد **كل** طلب في الدورة بهذا السبب.

أما الحمولة التي تتجاوز المركبات الموجودة فعلاً فتُنتج **Capacity shortage** بدلاً منه — انظر أدناه. والخلط بينهما سهل، واستجابتهما متعاكسة.

→ [الأسطول والمركبات](../configuration/fleet-and-vehicles.mdx)

:::

### No qualified driver

| | |
| --- | --- |
| **يعني** | لا سائق متاح يحمل المؤهل الذي يتطلبه هذا العمل |
| **تحقّق من** | `Master Data → Driver Qualifications` و`→ Driver Availability` |
| **العلاج** | أسند سائقاً مؤهَّلاً، أو سجّل المؤهل إن كان يحمله ولم يُسجَّل |

### Capacity shortage

| | |
| --- | --- |
| **يعني** | المركبات صالحة، لكن **هذه الحمولة لا تتّسع** على أيٍّ منها |
| **نص التفصيل** | *"Adding it to vehicle N exceeds capacity."* — ويسمّي المركبة |
| **تحقّق من** | وزن الشحنة وحجمها مقابل ملف سعة المركبة |
| **العلاج** | قسّم الشحنة، أو استخدم مركبة أكبر، أو زِد السعة، أو أعِد التخطيط لتاريخ آخر |
| **صعّد إلى** | من يملك الأسطول |

:::info[الفرق عن *No feasible vehicle* في سطر]

| السبب | المركبات… |
| --- | --- |
| **No feasible vehicle** | لم يُنظر فيها أصلاً — لا واحدة تُعلن ملف سعة |
| **Capacity shortage** | نُظر فيها، ولم تتّسع الحمولة |

**مُتحقَّق منه على `b2b`:** شحنة 460 كجم مقابل مركبة 250 كجم أنتجت **Capacity shortage** تسمّي المركبة. والطلبات نفسها مقابل مركبة بلا ملف سعة أنتجت **No feasible vehicle**.

:::

### Time-window conflict

| | |
| --- | --- |
| **يعني** | النافذة الموعودة وساعات عمل العقدة لا تجتمعان، أو نافذتان على مسار واحد تتعارضان |
| **تحقّق من** | **Service Commitment** في الطلب؛ وساعات عمل العقدة |
| **العلاج** | غيّر النافذة بتصريح، أو خطّطه كرحلة مستقلة |
| **صعّد إلى** | خدمة العملاء، إن كان الوعد نفسه هو المشكلة |

### Product incompatibility

| | |
| --- | --- |
| **يعني** | بضائع هذا الطلب لا يجوز أن تسافر مع بضائع وُضعت أصلاً |
| **تحقّق من** | `Master Data → Compatibility Groups` |
| **العلاج** | خطّطها على رحلات منفصلة |

### Route restriction

| | |
| --- | --- |
| **يعني** | قيد يمنع استخدام هذا المسار |
| **تحقّق من** | قيود المركبة؛ وقيود وصول العقدة |
| **العلاج** | استخدم مركبة مختلفة أو مساراً مختلفاً |

### Missing required data

| | |
| --- | --- |
| **يعني** | شيء تحتاجه الدورة غير موجود — عادةً إحداثيات العقدة أو منطقتها الزمنية أو ساعات عملها |
| **تحقّق من** | `Master Data → Locations` لكلا الطرفين |
| **العلاج** | أكمِل العقدة. ثم أعِد التخطيط |
| **صعّد إلى** | مسؤول النظام |

→ [عقد التخطيط](../configuration/planning-nodes.mdx)

### Customer location unavailable

| | |
| --- | --- |
| **يعني** | عقدة الوجهة غير مفتوحة في التاريخ المُخطَّط له |
| **تحقّق من** | نوافذ عمل العقدة |
| **العلاج** | أعِد التخطيط ليوم مفتوح، أو صحّح ساعات العمل |

### Planning horizon exceeded

| | |
| --- | --- |
| **يعني** | الطلب يقع خارج النافذة التي نظرت فيها هذه الدورة |
| **تحقّق من** | التاريخ المطلوب للطلب مقابل تاريخ الخطة |
| **العلاج** | خطّطه في تاريخه هو |

وهو غير ضار عادةً — فمعناه أن الطلب يخصّ يوماً آخر.

### Lower priority than available capacity permits

| | |
| --- | --- |
| **يعني** | خسر أمام عمل أهم. وذهبت السعة إلى غيره |
| **تحقّق من** | **Priority** للطلب؛ وما خُطِّط بدلاً منه |
| **العلاج** | ارفع الأولوية إن ضُبطت خطأً، أو زِد السعة، أو اقبله |

:::note[هذا أصح سبب يمكن رؤيته]

فمعناه أن النظام واجه خياراً حقيقياً واتخذه وفق ترتيب الأهداف. أما البقية فتشير غالباً إلى نقص أو خطأ في الإعدادات.

:::

## الإجراءات التالية السبعة

| الإجراء التالي | المعنى |
| --- | --- |
| **Replan for another date** | انقله ليوم فيه سعة |
| **Use another warehouse** | وفّره من مكان آخر |
| **Split the shipment** | قسّمه إلى حمولات تتّسع |
| **Request additional capacity** | احصل على مركبة أخرى |
| **Resolve missing data** | أكمِل الإعدادات |
| **Change the time window with authorization** | أعِد التفاوض على الوعد |
| **Perform an inter-warehouse transfer** | انقل المخزون إلى حيث يمكن إخراجه |

## العمل على القائمة

ترتيب عملي:

| # | افعل هذا | لأن |
| --- | --- | --- |
| 1 | جمّع حسب **Reason** | سبب واحد يهيمن عادةً |
| 2 | أصلِح أسباب الإعدادات أولاً — *Missing required data* و*No feasible vehicle* | إصلاحات لمرة واحدة تفكّ حجب طلبات كثيرة |
| 3 | ثم أسباب الجاهزية | يستطيع المستودع التصرف اليوم |
| 4 | ثم السعة والأولوية | هذه قرارات عمل حقيقية |
| 5 | أعِد التخطيط | `Planning → Generate a Plan` للتاريخ نفسه |

:::info[إصلاح الإعدادات مرة أفضل من إصلاح الطلبات مراراً]

إن عاد أربعون طلباً بسبب *Missing required data*، فلا تفتح أربعين طلباً. افتح العقدة التي يتشاركونها.

:::

## النزع من الخطة يكتب صفاً أيضاً

يُكتب صف طلب غير مخطَّط في حالتين:

| الحالة | المعنى |
| --- | --- |
| **تعذّر على الدورة وضعه** | الأسباب الاثنا عشر أعلاه |
| **نُزع من خطة**، أو أُلغيت خطته | عاد إلى **Eligible for Planning** |

والثانية هي سبب رؤيتك صفوفاً لطلبات كانت مخطَّطة سابقاً.

## التحقق

| تحقّق | أين |
| --- | --- |
| أي طلبات لم تتّسع | `Planning → Unplanned Demand` |
| هل نجح العلاج | أعِد التخطيط، ثم تحقّق من انخفاض العدد |
| النمط عبر الزمن | `Reporting → Unplanned Demand`، كمحاور |
| هل تحسّنت التغطية | [تغطية الخطة](../reporting/plan-coverage.mdx) |

## إذا كانت القائمة فارغة

| محتمل | تحقّق من |
| --- | --- |
| خُطِّط كل شيء | قارن بعدد رحلات الخطة — جيد فعلاً |
| لم تُجرَ دورة بعد | `Planning → Planning Runs` |
| القائمة مُرشَّحة | امسح شريط البحث |
| فشلت الدورة | الدورة الفاشلة لا تُنشئ خطة ولا صفوفاً غير مخطَّطة |
