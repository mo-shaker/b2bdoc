مصطلح واحد لكل مفهوم، يُستخدم باتساق في الدليل كله. ويُبقي هذا الجدول الاسم الإنجليزي بين قوسين ليستطيع القارئ مطابقته على الواجهة الإنجليزية.

## كائنات التشغيل

| المصطلح | المعنى في سطر واحد | مشروح في |
| --- | --- | --- |
| **الطلب (Demand)** | ما يجب أن يتحرك | [إدارة الطلب](../demand/demand-management.mdx) |
| **سطر الطلب (Demand Line)** | منتج وكمية داخل طلب، يحمل مالكه الخاص | [إدارة الطلب](../demand/demand-management.mdx) |
| **التخصيص (Allocation)** | المخزون المحدَّد المحجوز لسطر طلب | [أهلية التخطيط](../demand/planning-eligibility.mdx) |
| **الشحنة (Shipment)** | الوحدة القابلة للتخطيط — طلب أو أكثر يتحركان معاً | [إدارة الشحنات](../shipments/shipment-management.mdx) |
| **سطر الشحنة (Shipment Line)** | منتج وكمية داخل شحنة، يمكن تتبّعه إلى طلبه | [إدارة الشحنات](../shipments/shipment-management.mdx) |
| **جاهزية المستودع (Warehouse Readiness)** | هل يمكن للبضائع أن تتحرك فعلاً، ولماذا | [جاهزية المستودع](../readiness/warehouse-readiness.mdx) |
| **دورة التخطيط (Planning Run)** | محاولة واحدة لبناء خطة، بمدخلاتها وجوابها محفوظين | [دورات التخطيط](../planning/planning-runs.mdx) |
| **الخطة اليومية (Daily Plan)** | خطة التشغيل المقترحة ليوم واحد | [الخطة اليومية](../planning/the-daily-plan.mdx) |
| **الرحلة (Trip)** | مركبة واحدة وسائق ينفّذان سلسلة محطات | [الرحلات](../execution/trips.mdx) |
| **المحطة (Stop)** | زيارة فعلية واحدة أثناء الرحلة | [المحطات](../execution/stops.mdx) |

| **الحمولة (Load)** | ما هو على المركبة فعلياً، متتبَّعاً من الاقتراح إلى الإغلاق | [عمليات التحميل](../execution/loading-operations.mdx) |
| **مهمة التحميل (Loading Task)** | عمل المستودع لتحميل شحنة واحدة على مركبة | [عمليات التحميل](../execution/loading-operations.mdx) |
| **الطلب غير المخطَّط (Unplanned Demand)** | طلب لم تستطع الدورة إدراجه، مع السبب | [الطلب غير المخطَّط](../planning/unplanned-demand.mdx) |
| **الاستثناء التشغيلي (Exception)** | مشكلة تشغيلية مُسجَّلة تحتاج معالجة | [إدارة الاستثناءات](../exceptions/exception-management.mdx) |
| **إثبات التسليم (Proof of Delivery)** | التوقيع والصور والإحداثيات المُلتقطة عند المحطة | [إثبات التسليم](../execution/proof-of-delivery.mdx) |

## أنواع الطلب ومصادره

تصنّف SCOP كل طلب مرتين: بحسب **نوع الحركة**، وبحسب **مصدر المتطلب**. وكلاهما يُضبط تلقائياً من أدلة Odoo نفسه.

### نوع الطلب (Demand Type) — نوع الحركة

| القيمة | المعنى |
| --- | --- |
| **Delivery** | بضائع تخرج إلى عميل أو فرع |
| **Collection** | بضائع تُستلم |
| **Transfer** | حركة داخلية |
| **Return** | بضائع عائدة |
| **Inbound** | بضائع واردة من مورّد |

### نوع المصدر (Origin Type) — من أين جاء المتطلب

| القيمة | يُضبط حين |
| --- | --- |
| **Customer Order** | خلف التحويل أمر بيع |
| **Procurement Requirement** | خلف التحويل أمر شراء |
| **Return** | حركات التحويل مرتبطة بحركة سابقة |
| **Inter-Warehouse Movement** | تحويل داخلي بين مستودعين مختلفين |
| **Internal Replenishment** | تحويل داخلي داخل مستودع واحد |
| **Supplier Collection** | تحويل وارد بلا أمر شراء |
| **Branch Request** | تحويل صادر بلا أمر بيع |
| **Customer-Owned Movement** | يُضبط يدوياً حيث تكون البضائع المنقولة للعميل |
| **Urgent Request** | يُضبط يدوياً |
| **Corrective Follow-Up** | يُضبط يدوياً |

والقيم الثلاث الأخيرة لا تُستنتج أبداً. وتبقى قابلة للتعديل ما دام الطلب في **Draft**.
