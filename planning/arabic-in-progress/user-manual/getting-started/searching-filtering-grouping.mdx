## الغرض

تُحلّ معظم أسئلة SCOP بإيجاد السجل الصحيح بسرعة. وتغطي هذه الصفحة سلوك البحث الخاص بـ SCOP.

## البحث بالمعرِّف التجاري

أسرع طريق إلى أي سجل في SCOP هو معرِّفه المطبوع.

| اكتب هذا | تجد |
| --- | --- |
| `DMD-2026-000010` | ذلك الطلب |
| `SHP-2026-000006` | تلك الشحنة |
| `PLN-2026-08-25-01` | تلك الخطة اليومية |
| `TRP-2026-000005` | تلك الرحلة |

والمعرِّفات **ثابتة**. فما إن تُخصَّص حتى لا تتغير أبداً، ولذلك يمكن اقتباسها بأمان في رسالة أو تذكرة.

## البحث بمستند المصدر

يحمل الطلب رقم الأمر الذي جاء منه — `S09520` مثلاً. والبحث عن ذلك الرقم في قائمة الطلبات يجده دون الحاجة إلى أي صلاحية على الأمر نفسه.

راجع [كيف تُنشأ الطلبات](../demand/how-demands-are-created.mdx).

## الفلاتر التي تُطبِّقها SCOP نيابةً عنك

تُفتح عدة شاشات وفلتر مُطبَّق أصلاً. ومعرفة أيها يوفّر ارتباكاً حين «يختفي» سجل تتوقعه.

| الشاشة | تُفتح مُرشَّحة على | لماذا |
| --- | --- | --- |
| `Operations → Exceptions` | الاستثناءات المفتوحة | المشكلات المغلقة تاريخ |
| `Reporting → OTIF` | السجلات التي تحمل التزاماً | التسليم بلا وعد لا يمكن قياسه مقابل وعد |
| `Reporting → Unplanned Demand` | مجمَّعة حسب السبب | السبب هو المقصود |
| `Reporting → Ownership Data Quality` | مجمَّعة حسب الحل | تُظهر المحلول مقابل غير المحلول في لمحة |
| `Reporting → Vehicle Utilization` | مجمَّعة حسب المركبة | |
| `Reporting → Trip Planned vs Actual` | الرحلات المكتملة والمكتملة جزئياً | الرحلة الجارية بلا قيم فعلية |
| `Reporting → Decision Quality` | مجمَّعة حسب ما إذا عُدِّلت الخطة | |
| `Reporting → Failed Projections` | الأحداث الفاشلة فقط | |
| `Reporting → Orphan Moves` | الحركات التي لا يغطيها سطر طلب | |
| `My Work → My Trips` | رحلاتك أنت، المُطلَقة فما بعد | |
| `My Work → My Stops` | محطات تلك الرحلات | |

:::warning[السجل الذي يبدو مفقوداً عادةً مُرشَّح لا غائب]

قبل أن تستنتج أن SCOP لم تُنشئ شيئاً، امسح شريط البحث بالكامل. وهذا أكثر إنذار كاذب شيوعاً أثناء اختبار القبول.

:::

## التجميع حسب الحالة

يعمل `Group By ▸ Status` على الطلبات والشحنات والخطط والرحلات والاستثناءات، ويعرض **كل حالات دورة الحياة بما فيها الفارغة**، بترتيب دورة الحياة.

وهذا أسرع فحص صحة يومي: جمّع قائمة الطلبات حسب الحالة، وكل ما تراكم في **Submitted** أو **Validated** هو عمل ينتظر أحداً.

## تجميعات مفيدة بحسب الدور

| الدور | الشاشة | جمّع حسب | يخبرك |
| --- | --- | --- | --- |
| المخطِّط | Demands | Status | ما المتوقف، وأين |
| المخطِّط | Unplanned Demand | Reason | أي قيد يكلّفك أكثر |
| المستودع | Warehouse Readiness | Readiness | ما الذي ما زال يحتاج تجهيزاً |
| المستودع | Loading Tasks | Status | ما الذي يحتجز مركبة عند البوابة |
| مدير العمليات | Daily Plans | Status | ما الذي ينتظر الاعتماد |
| مدير العمليات | Exceptions | Severity ثم Owner | من يحمل المشكلات الحاجبة |
| الإدارة | OTIF | العميل ثم الشهر | أداء الخدمة |

## المفضّلة

أي بحث تبنيه — بفلاتره وتجميعه — يمكن حفظه كمفضّلة، وجعله افتراضياً لتلك الشاشة إن شئت. وهذه الطريقة الصحيحة لإعطاء فريق مستودع عرض «عمل اليوم» دون تغيير شيء لأحد آخر.

## الأنشطة والإشعارات

تستخدم SCOP نظام أنشطة Odoo القياسي في موضع واحد تحديداً: **إسناد استثناء يُنشئ نشاطاً لمالكه**، فيظهر في قائمة أنشطة ذلك الشخص بدل شاشة قد لا يفتحها.

وكل ما عدا ذلك يصلك بـ **متابعة** السجل. فمتابعة طلب أو خطة أو رحلة تعني وصول تغيّرات حالتها ورسائلها إلى صندوق واردك.

| تريد | افعل هذا |
| --- | --- |
| أن تُخطَر عند اعتماد خطة بعينها | تابِع الخطة |
| أن تُخطَر عند إسناد استثناء إليك | لا شيء — يصل النشاط تلقائياً |
| نظرة عامة يومية | استخدم [لوحة المعلومات](../reporting/the-dashboard.mdx) أو مفضّلة محفوظة |

:::note[لا ترسل SCOP تنبيهات تشغيلية آلية في الإصدار الأول]

لا يوجد تنبيه بريدي لرحلة متأخرة أو طلب غير مخطَّط. فتُقرأ هذه من [التقارير](../reporting/reporting-overview.mdx). والإشعار الآلي الوحيد هو تصعيد الاستثناء، الذي يُخطر المجموعة المسؤولة عند خرق اتفاقية مستوى الخدمة.

:::
