## مسؤوليتك

أنت تقرّر **ما الذي تتفاعل معه SCOP**، و**أين تستطيع التوجّه**، و**من يحقّ له التصريح بماذا**. وأنت الدور الوحيد الذي يقرأ أدوات التشخيص التقنية.

وترث كل ما يستطيعه مدير العمليات والإدارة — مع الاستثناء نفسه الذي يسري على الجميع.

:::danger[الصلاحيات الإدارية لا تمنح صلاحية اعتماد]

يرفض `BR-PLN-001` اعتماد خطة من مؤلفها، **وأنت منهم**. وهذه ليست صلاحية تُمنح، بل فصل مهام.

**مُتحقَّق منه على `b2b`:** رُفض اعتماد مسؤول النظام لخطة أنشأها بنفسه بالرسالة *«was created by you, so you may not approve it. Separation of duties is the point of the approval step.»*

:::

| الشاشة | ما تضبطه | الفصل |
| --- | --- | --- |
| `Technical → Pilot Scope` | أي أنواع عمليات Odoo تولّد طلباً، ومن متى | [نطاق التجربة](../configuration/pilot-scope.mdx) |
| `Master Data → Locations` | عقد التخطيط التي تستطيع SCOP التوجّه إليها | [عقد التخطيط](../configuration/planning-nodes.mdx) |
| `Master Data → Import Locations` | إنشاء العقد بالجملة | [عقد التخطيط](../configuration/planning-nodes.mdx) |
| `Governance → Approval Authorities` | من يجوز له أي إجراء على أي كائن | [نموذج الحوكمة](../concepts/the-governance-model.mdx) |
| `Governance → Feature Flags` | مفاتيح السلوك الاختياري | أدناه |
| `Master Data → Onboarding` | معالجات الإطلاق الثلاثة بالترتيب | [التهيئة والترحيل](../configuration/onboarding-and-migration.mdx) |
| `Technical → Releases` | سجلات الإصدارات لهذا التنصيب | [نطاق التجربة](../configuration/pilot-scope.mdx) |

## الإعدادان اللذان يوقفان كل شيء

يعود معظم بلاغات *«SCOP لا تفعل شيئاً»* إلى أحدهما.

| الإعداد | إن كان خاطئاً |
| --- | --- |
| **نطاق التجربة غير مُطبَّق**، أو نوع العملية غير مُفعَّل | **لا يُنشأ أي طلب إطلاقاً.** فـ SCOP لا تتفاعل إلا مع العمليات المُهيّأة |
| **عقدة تخطيط مفقودة** لمصدر أو وجهة | لا طلب لذلك التحويل، لكن يُسجَّل حدث `DemandGenerationSkipped` يسمّي الموقع غير المربوط |

ولا يفشل أيٌّ منهما بصخب في لحظته، ولذلك هما أول ما يُفحص. راجع [تشخيص العقدة المفقودة](../configuration/missing-node-diagnostics.mdx).

## أدوات التشخيص التي تملكها

| الشاشة | ما تخبرك به |
| --- | --- |
| `Technical → Domain Events` | كل حقيقة سجّلتها SCOP عمّا فعلته أو امتنعت عنه |
| `Reporting → Failed Projections` | أين أخفقت SCOP في تسجيل شيء، ولماذا |
| `Reporting → Orphan Moves` | حركات مخزون على تحويل مولِّد للطلب لا يغطيها سطر طلب |
| `Reporting → Ownership Data Quality` | كم من الملكية ما زال غير محلول |
| `Technical → Execution Events` | ما حدث فعلياً أثناء الرحلات |
| `Technical → Capacity Snapshots` | حمولة المركبة عند كل نقطة من كل مسار |
| `Technical → Sequence Counters` | العدّادات خلف المعرِّفات التجارية |
| `Technical → Travel Matrix` | المسافات والمدد المخزَّنة بين العقد |

### قراءة أحداث المجال

أحداث المجال هي الجواب عن *«هل رأت SCOP هذا أصلاً؟»*

| اسم الحدث | المعنى |
| --- | --- |
| `DemandGenerated` | أُنشئ طلب لهذا التحويل |
| `DemandGenerationSkipped` | رأت SCOP التحويل و**امتنعت عمداً** — ويسمّي السجل الموقع غير المربوط و**أي طرف** من الحركة تعذّر حلّه |

:::info[العلامتان مفصولتان عمداً]

لا يُسجَّل التخطّي أبداً على أنه *«عولج»*. فلو كان كذلك، لما فعل ربط الموقع لاحقاً وإعادة حفظ التحويل شيئاً، لأن SCOP ستظن العمل منجزاً.

:::

### الإسقاطات الفاشلة

توليد الطلب **غير حاجب بالتصميم**: فإن فشل، يُتراجع عنه وحده و**يُحفظ التحويل على أي حال**. فلا يجوز أن يعجز عامل مستودع عن تسجيل حركة لأن إسقاطاً تخطيطياً فيه خلل.

وثمن ذلك أن الإخفاقات صامتة في لحظتها. وهي ظاهرة في `Reporting → Failed Projections`، وتستحق نظرة يومية أثناء التجربة.

## مفاتيح الخصائص

يبدّل `Governance → Feature Flags` سلوكاً اختيارياً. ولكل مفتاح **مالك** و**غرض** و**نطاق بيئة** و**تاريخ انتهاء إلزامي**.

وعامِل المفتاح كقرار على مستوى التنصيب، لا كطريقة للالتفاف على قاعدة عمل.

## التهيئة بالترتيب

الترقيم ليس زخرفياً — كل خطوة تعتمد على سابقتها.

```text
1 · Consignment Partners   علّم الشركاء الذين نحتفظ ببضائعهم
        ↓
2 · Inventory Ownership    رحّل الملكية على المخزون القائم
        ↓
3 · Pilot Readiness        تحقّق من استيفاء متطلبات الانطلاق
```

التفصيل الكامل: [التهيئة والترحيل](../configuration/onboarding-and-migration.mdx).

## ما ينبغي ألّا تفعله

| تجنّب | لماذا |
| --- | --- |
| تحرير حالة محكومة مباشرةً | يتخطى الفحوص الخاصة بالانتقال. و SCOP ترفضه أصلاً |
| إضافة `SCOP User` إلى سائق | يُبطل نموذج أمان السائق بصمت |
| إعادة تشغيل توليد الطلب على التاريخ | لا يوجد استرجاع عمداً. وتاريخ تخطيط مُعاد بناؤه خيالٌ يُقدَّم كدليل |
| منح المخطِّطين Fleet → Officer بدل Administrator | Officer يحصر المستخدم في المركبات التي يقودها بنفسه |
| تعليق قاعدة عمل لتجاوز رفض | استخدم [إعفاء قاعدة](../concepts/the-governance-model.mdx)، فهو مُصرَّح به ومحدَّد المدة |

## إذا كان هناك خلل

| العَرَض | تحقّق من |
| --- | --- |
| لا طلبات إطلاقاً | نطاق التجربة غير مُطبَّق، أو نوع العملية خارجه |
| طلبات لبعض الوجهات فقط | عقد تخطيط مفقودة — راجع `DemandGenerationSkipped` |
| طلبات تظهر ولا شيء قابل للتخطيط | عقد تنقصها إحداثيات أو منطقة زمنية أو ساعات عمل |
| التغطية أقل من الحقيقة | `Reporting → Orphan Moves` يُظهر حركات لا يغطيها سطر طلب |
| مخطِّط لا يستطيع اعتماد شيء | راجع `Governance → Approval Authorities` للكائن والإجراء |
| الملكية تحجب كل شيء | شركاء الأمانة غير مُعلَّمين، أو الملكية لم تُرحَّل |
