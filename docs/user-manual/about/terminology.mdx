## Demand types and origins

SCOP classifies every demand twice: by **what kind of movement it is**, and by **where the
requirement came from**. Both are set automatically from Odoo's own evidence.

### Demand Type — the kind of movement

| Value | Meaning |
| --- | --- |
| **Delivery** | Goods going out to a customer or branch |
| **Collection** | Goods being picked up |
| **Transfer** | An internal movement |
| **Return** | Goods coming back |
| **Inbound** | Goods arriving from a supplier |

### Origin Type — where the requirement came from

| Value | Set when |
| --- | --- |
| **Customer Order** | The transfer has a sales order behind it |
| **Procurement Requirement** | The transfer has a purchase order behind it |
| **Return** | The transfer's moves link back to an earlier move |
| **Inter-Warehouse Movement** | An internal transfer between two different warehouses |
| **Internal Replenishment** | An internal transfer within one warehouse |
| **Supplier Collection** | An incoming transfer with no purchase order |
| **Branch Request** | An outgoing transfer with no sales order |
| **Customer-Owned Movement** | Set by hand where goods being moved belong to the customer |
| **Urgent Request** | Set by hand |
| **Corrective Follow-Up** | Set by hand |

The last three are never inferred. They stay editable while the demand is in **Draft**.
