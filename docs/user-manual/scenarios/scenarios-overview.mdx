## What these are

The reference chapters explain one screen at a time. These scenarios take **one operational
situation** end to end, across every role and every screen it touches.

They are written to be **followed**, not only read. Each one names the roles, the records and
the order.

## The demo records

The scenarios use one continuing story, so a reader following them in order recognises the
records.

| Identifier | Role in the story |
| --- | --- |
| **SCOP Manual Demo Customer** | The parent commercial customer |
| **SCOP Manual Branch A** | A planning node, normal deliveries |
| **SCOP Manual Branch B** | A second branch — proves a different branch is a different visit |
| **SCOP Manual Branch C** | Deliberately **without** a planning node |
| **SCOP Manual Vehicle** | Small capacity, so infeasibility can be demonstrated honestly |
| **SCOP Manual Driver** | A driver with an employee and user link |
| **SCOP Manual Consignment Supplier** | A partner flagged as a consignment owner |

:::note[Your identifiers will differ]

The reference numbers in these pages — `DMD-2026-000010` and so on — are examples. Yours will
be different. The **shapes** are what matter.

:::

## Before you start any of them

| Prerequisite | Check |
| --- | --- |
| Pilot scope is **Applied**, with the right operation types | `Technical → Pilot Scope` |
| Planning nodes exist and are complete | `Master Data → Locations` |
| At least one vehicle has a capacity profile | The vehicle's SCOP fields |
| At least one driver's employee is linked to a user | Odoo Employees |
| **Two** people can approve plans | `Governance → Approval Authorities` |
| Planners hold Fleet → Administrator, Employees → Officer, Inventory → User | The user record |

:::danger[The prerequisite that stops a solo tester]

`BR-PLN-001` refuses approval by the plan's own author, including for an Administrator.

**One person cannot complete a SCOP cycle.** Arrange a second approver before you start.

:::
