## Where loading is recorded

A released trip must be loaded before it can depart. The trip's own lifecycle carries this:

```text
Released → Loading → Ready to Depart → In Progress → Completed
```

**Role**
Warehouse

**Navigate to**
`SCOP → Operations → Loading Tasks` — the warehouse's own work list, described below. The trip follows it.

A **dispatcher** can also drive the same transitions from the trip itself (`SCOP → Operations → Trips` → open the released trip → **Start Loading**, **Loading Done**), which is what they do for a trip that carries no shipments. A warehouse user cannot: they hold no write access to the trip, deliberately, and work entirely from their own task list. The trip follows.

**What SCOP does**
Records the transition times, so the elapsed loading duration becomes a measurable figure rather than an impression. Warehouse-caused delay is one of the Warehouse Productivity measures.

**Expected result**
The trip reaches **Ready to Depart**, and the driver's **Depart** button becomes available.

## The Loading Tasks screen

**Role**
Warehouse

**Navigate to**
`SCOP → Operations → Loading Tasks`

Releasing a trip creates **one loading task per shipment on board**, in **Pending**.

<Screenshot
  src="quick-start/22-loading-tasks.png"
  alt="SCOP Loading Tasks list showing one Pending task, Load SHP-2026-000001, with its shipment, trip, vehicle, planned duration and Start button."
  caption="Released the plan, and the work list filled itself: one task per shipment on the trip, Pending, with a Start button. Nobody created these by hand."
/>

Each carries the shipment, the trip, the vehicle, a planned duration taken from the origin node's service-duration model, and an **Assigned To** field so the work can be given to a named person.

**What to do**

1. Press **Start** on the task when the crew begins loading that shipment. SCOP stamps the start time, and the **trip** moves to **Loading**.
2. Load the shipment.
3. Press **Done**. SCOP stamps the completion time and computes the **actual loading duration**, then refreshes the shipment's readiness.

<Screenshot
  src="quick-start/27-loading-task-in-progress.png"
  alt="SCOP Loading Tasks list with the task In Progress and a Done button offered."
  caption="After Start: the task is In Progress and the trip has moved to Loading. Done is the only remaining action."
/>

When the last task on a trip is settled, the trip moves to **Ready to Depart** on its own. You do not need to go back to the trip form.

:::info[An open loading task keeps the vehicle at the gate]

**Loading Done** on the trip is refused while any task is still Pending or In Progress, naming the tasks that are outstanding. A vehicle that leaves before its loading is recorded makes every actual loading duration meaningless, and there is no honest way to reconstruct one afterwards.

A task nobody will do can be **Cancelled**, which counts as settled.

:::

**Why this matters for measurement**

The per-shipment actual duration is what makes warehouse-caused delay measurable at the grain it actually occurs. The trip's own transitions only tell you how long the whole vehicle took.

## What you should not do here

:::info[Quantities never come from the loading step]

Do not attempt to record delivered quantities while loading, and do not expect to type them into SCOP later.

**Actual quantities come from the Odoo transfer.** The warehouse validates the delivery order in Odoo, and SCOP reads the result back. This is covered in [Step 7 — Driver Delivery](./driver-delivery.mdx), where you will see the driver's own screen state plainly: *"Quantities come from the warehouse transfer. Record a short delivery there, not here."*

:::

**If it does not work**

| Symptom | Check |
| --- | --- |
| **Start Loading** is not offered | The trip is not **Released**. A trip only reaches Released when its plan is released |
| The trip is still **Draft** after the plan was released | The plan carries its trips with it — generation makes them **Recommended**, submission **Under Review**, approval **Approved**, release **Released**. A trip left in Draft was not part of that plan |
| **Loading Done** is refused | A loading task is still open. The message names them. Finish or cancel them first |
| Loading Tasks is empty for a released trip | The trip carries no shipments. Loading tasks are created per shipment on board |
