## Step 4 — Generate a daily plan

**Role**
Planner / Dispatcher

**Navigate to**
`SCOP → Planning → Generate a Plan`

**What to do**

1. Set the **Plan Date** to the operating day you are planning.
2. Review the **Eligible Demand** SCOP has offered.
3. Review the **Available Vehicles**.
4. Leave **Planned By** on the baseline provider unless you intend to plan by hand.
5. Click **Generate**.

<Screenshot
  src="quick-start/13-generate-plan-wizard.png"
  alt="SCOP Generate a Daily Plan wizard showing plan date, objective profile, planned by, timeout, eligible demand and available vehicles."
  caption="The planning wizard. Setting the plan date refills the demand and vehicle lists for that day."
/>

**1 — Plan Date**
The operating day the plan covers. Changing it re-offers what is actually plannable that day: eligible demand required on or before the date, and vehicles available across the whole day.

**2 — Objective Profile**
Which objective hierarchy the recommendation optimises against — how it balances service, utilisation, and cost. The default profile is pre-selected.

**3 — Planned By**
The decision provider:

| Provider | Behaviour |
| --- | --- |
| SCOP Decision Service (baseline) | Produces a deterministic recommendation. This is the normal choice. |
| SCOP Decision Service (manual) | Validates and scores **your** assignments instead of recommending its own. |

Choosing manual is a deliberate act with a record, not a bypass — both providers produce the same shape of answer, which is what lets a hand-built plan be compared against a recommendation later.

**4 — Eligible Demand**
The demand SCOP will try to place. Only demand at **Eligible for Planning** appears here.

**5 — Available Vehicles**
Vehicles with a capacity profile and availability on the selected date.

**6 — Generate**
Starts the planning run.

:::note

The **Assignments** grid only appears when you choose the manual provider. On the baseline provider the wizard tells you plainly: *"The baseline recommends; your assignments below are ignored."*

:::

## What SCOP creates

One click produces four things:

| SCOP creates | Where to find it |
| --- | --- |
| **Planning Run** — the question, its inputs and its answer | `SCOP → Planning → Planning Runs` |
| **Daily Plan** — the proposed plan | `SCOP → Planning → Daily Plans` |
| **Recommended Trips** — inside the plan | on the plan's **Trips** tab |
| **Unplanned Demand** — anything it could not place, with a reason | `SCOP → Planning → Unplanned Demand` |

### The planning run

<Screenshot
  src="quick-start/14-planning-runs.png"
  alt="SCOP Planning Runs list showing RUN-2026-000001 in state Recommended with the baseline provider."
  caption="RUN-2026-000001 — requested at 13:34, for plan date 18/08, provider baseline, 1 demand in, 0 unplanned, 1 000 ms timeout. State: Recommended."
/>

The run is created **before** the provider is called, so a provider that hangs or dies still leaves a row explaining what was attempted. Every run keeps its request and its response, so a historical plan stays replayable.

### The daily plan

<Screenshot
  src="quick-start/15-daily-plan-list.png"
  alt="SCOP Daily Plans list showing PLN-2026-08-18-01 created by Paula Planner in state Generated."
  caption="PLN-2026-08-18-01 — one trip, no unplanned demand, created by Paula Planner. State: Generated."
/>

**Expected result**
A plan exists in state **Generated**, with at least one recommended trip.

**Verify**
Open the plan.

<Screenshot
  src="quick-start/16-daily-plan-form.png"
  alt="SCOP Daily Plan form showing the plan header, decision quality fields, and the Trips, Unplanned Demand, Approvals and Recommendation tabs."
  caption="The plan form. Four tabs: Trips, Unplanned Demand, Approvals, and Recommendation — the untouched provider answer kept for comparison."
/>

The plan's own lifecycle is on the status bar:

```text
Generated → Under Review → Approved → Released
```

The **Decision Quality** block on the form is filled in as you work: whether the recommendation was modified, how many times, by whom, and with what override reason. That record is the most valuable output of a pilot.

:::info[The Recommendation tab never changes]

It holds the provider's answer **before** any human edit, written once at generation. It is the baseline every Decision Quality measure is taken against — which is why nothing can rewrite it.

:::

**If it does not work**

| Symptom | Check |
| --- | --- |
| **Eligible Demand** is empty | No demand is at **Eligible for Planning** for that date, or the required date is after the plan date |
| **Available Vehicles** is empty | No vehicle has a capacity profile, or none is available on that date — `SCOP → Master Data → Vehicle Availability` |
| `Access Error` on `Vehicle` | Your user needs the Odoo **Fleet → Officer** group as well as its SCOP role |
| The run is **Failed** | Open the run; it records what the provider was asked and what came back |
| Demand appears under Unplanned | Expected behaviour — see [Unplanned Demand](../exceptions/unplanned-demand.mdx) |
